### รูปแถว

- **บรรทัดบน** — ไอคอนประจำสกิล + ชื่อสกิล (ตัวหนา `#f1f5f9`) + เจ้าของ · ของตัวเองเขียน "ตัวเอง" ไม่ซ้ำชื่อตัวที่กำลังเปิดดู · ของฝ่ายตรงข้ามต่อท้าย "· ฝ่ายศัตรู"
- **บรรทัดล่าง** — ไอคอนของผล + ผลพร้อมตัวเลขจริง (`#e2e8f0` เล็กลงนิด แต่ยังอ่านสบาย)
- ป้ายสถานะ (`2/3 ชั้น` · `ใช้ไปแล้ว`) เกาะขวาบรรทัดล่าง เพราะขยายความ "ผล" ไม่ใช่ชื่อสกิล

### กลไก — `utils/battleBuffs.js` (pure + มีเทส)

```js
/** ผูก effect เข้ากับ "ตัวที่เป็นเจ้าของ" → ได้ที่มา
 *  (statusMap วันนี้ทิ้งที่มา เพราะเก็บแค่ Set ของ effect) */
buffSources(teamA, teamB) → { A0: [ {effect, icon, label, skillName, skillIcon,
                                    ownerUid, ownerName, ownerEmoji, buff, self, foeSide} ], ... }

/** เติมสถานะสดจาก beat ที่เล่นไปแล้ว */
liveBuffs(sources, beats, idx) → เหมือนบน + { stacks, spent }
```

- `liveBuffs` อ่าน `beats.slice(0, idx + 1)`:
  - `stackAtk` → `stacks` = `amount` ของ event ล่าสุด (เอนจินส่ง `killer.atkStacks` มาให้แล้ว)
  - `revive` / `cheatDeath` / `saveAlly` → เห็น event = `spent: true`
- ครอบ `duoRegen` (💧 วาฬ🔗แมวน้ำ) ที่วันนี้ไม่มีป้ายเลย — ต้องเพิ่ม `STATUS_ICON.duoRegen = '💧'` + `STATUS_TEXT.duoRegen` · เจ้าของ = ตัวที่มี `teamAtk` + `duoWith` ครบคู่
- **`statusMap` ใน `BattleReplay` เปลี่ยนไปเรียก `buffSources` แทน** (แหล่งความจริงเดียว) แล้วตัดที่มาทิ้งตอนทำป้าย — ไอคอนบนการ์ดต้องเหมือนเดิมเป๊ะ รวมเพดาน `STATUS_MAX`

### 🔒 ไม่ชนกฎเหล็ก perf

`statusMap` ถูกออกแบบให้ static ทั้งไฟต์เพราะ "ห้ามแก้ป้ายขณะการ์ดมีอนิเมชันวิ่งอยู่" (เปลี่ยน paint กลางอากาศ = re-raster ทั้งการ์ด)

`liveBuffs` คำนวณ **ตอนเปิดหน้าต่าง inspect** ซึ่ง `inspect()` สั่ง `paused = true` + `clearTimeout(timer)` ไปแล้ว → ไม่มีการ์ดใบไหนมีอนิเมชันวิ่ง · ป้ายบนการ์ดยังนิ่งเหมือนเดิมทุกประการ

## 4. เลขบนการ์ดในรีเพลย์ วิ่งตามสกิลที่ทำงาน

### เจตนา (user สั่ง 30 ส.ค.)

ค่าพลังก่อนเริ่มสู้ = **ค่าดิบ** ตามที่เห็นตอนจัดทีม แล้วพอเริ่มสู้ สกิลทำงาน เพิ่มเลือดทั้งทีม → **เลขบนการ์ดต้องขยับให้เห็น** ไม่ใช่แอบเป็นค่าหลังบัฟมาตั้งแต่ต้น

| จังหวะ | ATK / HP บนการ์ด |
|---|---|
| READY–GO | ค่าดิบ ตามที่เห็นตอนจัดทีม |
| 🐳 คุณวาฬเปล่งออร่า (`teamHp`) | เลข HP ทั้งทีมขยับขึ้นตรงนั้น |
| 🦖 ทีเร็กซ์ล้มศัตรูได้ 1 ตัว (`stackAtk`) | ATK ของ 🦖 ขยับขึ้นทีละชั้น |
| เปิด inspect | อ่านได้ว่าตอนนี้เท่าไหร่ + มาจากอะไร (ข้อ 3) |

### 🐞 บั๊กที่มีอยู่วันนี้ซึ่งงานนี้ซ่อมไปด้วย

`BattleReplay.buildMax()` คำนวณ ATK/HP จาก `buildCombatant(p)` ล้วน **ไม่ผ่าน aura** แต่ log ส่ง `targetHpAfter` มาบนสเกลที่ผ่าน aura แล้ว ⇒ ทีมที่มีวาฬ (เลือด +10%) หลอดเลือดเริ่มเกิน 100% และเลข HP ผิดตั้งแต่หมัดแรก (`hp.value` ไม่มี clamp บน)

### กลไก — ไม่คำนวณซ้ำ ให้เอนจินบอกมาเลย

`applyAuras` / `runOnKill` แนบ `statsAfter: { A0: {atk, maxHp}, ... }` ไปกับ event ที่มันเปลี่ยนค่าจริง (snapshot หลังทำงานเสร็จ) → รีเพลย์แค่ **assign** ตอน beat นั้นเล่นถึง

**ไม่มีสูตรฝั่ง UI = ไม่มีทางคลาดจากเอนจิน** (ถ้าให้ UI คำนวณ aura เอง วันที่สูตรเปลี่ยน จะมีสองแหล่งความจริงทันที)

`simulateBattle` คืน `units: { A0: {atk, maxHp}, ... }` เพิ่มใน result = snapshot **หลัง aura ก่อนหมัดแรก**

⚠️ **สองข้อห้ามของการเติมของลง log** (บทเรียน `fxKind` 29 ส.ค. — CLAUDE.md ข้อ 15)

1. **ห้ามสร้าง event ชนิดใหม่ลง log** — `buildBeats` pass 3 ตกท้ายไปที่สาขา attack (`battleBeats.js:187`) ที่อ่าน `ev.dead`/`ev.sub` จะพังทันที · `units` จึงไปอยู่บน `result` ไม่ใช่ใน `log`
2. **ก่อนตั้งชื่อฟิลด์ใหม่บน event ต้อง grep ชื่อนั้นที่ปลายทางก่อน** — `buildBeats` ประกอบ beat ด้วย `{ ...ev, kind, ... }` ⇒ ฟิลด์ชื่อซ้ำถูกทับเงียบ คอมไพเลอร์ไม่เตือน เทสเดิมไม่จับ · ตรวจ: `grep -rn "statsAfter" src/` ต้องไม่เจออะไรก่อนเริ่ม แล้วเจอเฉพาะจุดที่เราเพิ่มหลังจบ

`statsAfter` แนบไปกับ event `t: 'passive'` ที่ `buildBeats` รู้จักอยู่แล้ว จึงปลอดภัย

### ⚠️ สองตัวแปร คนละหน้าที่ ห้ามปน (จุดพลาดง่ายสุดของงานนี้)

| ตัวแปร | คือ | ใช้ทำอะไร | reactive? |
|---|---|---|---|
| `maxHp` (plain object เดิม) | ค่า**หลัง aura** ของเอนจิน จาก `result.units` | ตัวหารของ `hp%` + ป้อน `buildBeats` เท่านั้น | **ห้าม** — ถ้าทำเป็น ref แล้ว `beats` จะ re-compute กลางไฟต์ ขณะที่ `idx` ชี้เข้าอาเรย์เก่า = พังทั้งไฟต์ (มีคอมเมนต์เตือนไว้แล้วที่ `BattleReplay.vue:352`) |
| `dispStats` (ref ใหม่) | เลขที่**พิมพ์บนการ์ด** | `atkOf()` / `curHp()` / `ticksFor()` | ใช่ — เริ่มที่ค่าดิบ แล้ววิ่งตาม `statsAfter` |

- `result.units` ไม่มี (log เก่า/เทสเก่า) → `maxHp` ตกกลับไป `buildCombatant` เหมือนเดิม
- `reset()` ต้องคืน `dispStats` เป็นค่าดิบด้วย ไม่งั้นไฟต์ที่ 2 จะเริ่มด้วยเลขบัฟของไฟต์ก่อน (เคสเดียวกับบั๊ก fx re-attach 18 ก.ค.)

### perf

- aura ทั้งหมดเล่นในกลุ่มเปิด (`openGroup`/`openQuiet`) ตอนที่ยังไม่มีการ์ดใบไหนมีอนิเมชัน → เปลี่ยนเลขตรงนั้นไม่ชนกฎเหล็ก
- ⬆️ สแต็กเกิดได้สูงสุด **3 ครั้งต่อไฟต์** (เพดาน `max: 3` ของ trex) เกาะ beat ของ passive ที่ไม่มีอนิเมชันการ์ดเป็นของตัวเอง — ถ้ามาตรวัดเฟรม (`?fps=1`) จับได้ว่ากระตุก ถอยไปอัปเดตตอนต้นรอบแทน
- หลอดเลือดไม่ต้องมีอนิเมชันเพิ่ม — `hp%` ยังเป็น 100 ที่ขยับคือตัวเลขกับขีดบอกระดับ (`ticksFor`)

## เทส

**`battleBuffs.test.js` (ใหม่)**
- ที่มาถูกตัว — วาฬในทีมเรา → `❤️` โผล่บนทุกใบฝั่งเรา พร้อม `ownerUid` ของวาฬ
- ข้ามฝั่งถูกทาง — นกฮูกอยู่ทีมศัตรู → `🎯` โผล่บน**ทีมเรา** ติดธง `foeSide`
- `self` — พาสสีฟติดตัว (dodge/thorns) ขึ้นเฉพาะเจ้าตัว
- `stacks` นับตาม `idx` — หยุดที่ beat ก่อนฆ่า = 0 ชั้น · หลังฆ่า 2 ตัว = 2 ชั้น
- `spent` — เห็น event revive แล้วต้องเป็น true
- `duoRegen` โผล่ครบทีมเมื่อมีวาฬ+แมวน้ำ และไม่โผล่เมื่อมีตัวเดียว
- ป้ายบนการ์ด (`statusMap` ที่ derive ต่อ) ยังได้ผลเท่าเดิม รวมเพดาน `STATUS_MAX`

**`battleEngine.test.js` (เพิ่ม)**
- `result.units` มีครบทุก uid ของทั้งสองทีม
- ทีมมีวาฬ → `units.A0.maxHp` = ค่าดิบ × 1.10 (ตรงกับ aura ที่ใส่จริง)
- `statsAfter` มีเฉพาะบน event ที่เปลี่ยนค่าจริง (aura teamHp/teamAtk, stackAtk) ไม่มีบน teamCrit/enemyVuln ที่ไม่แตะ atk/maxHp
- `statsAfter` ของ event สุดท้าย = สเตตัสจริงของยูนิตในจังหวะนั้น

**เทสเดิมต้องไม่แดง** — `battlePassives.test.js`, `battleBeats.test.js`, `battleSummary.test.js`

## ลำดับงาน

1. `battleEngine` — `result.units` + `statsAfter` + เทส (ไม่มีใครพึ่งพา ทำก่อนได้)
