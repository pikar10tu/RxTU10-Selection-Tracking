# สเปก: ฟาร์มมีชีวิต — พืชโตเป็นระยะ + เอฟเฟกต์เก็บเกี่ยว/ขาย

วันที่ 22 ส.ค. 2026 · brainstorm กับ user เสร็จแล้ว (อนุมัติดีไซน์ 22 ส.ค.)

## ที่มา

user อยากอัพเกรดระบบเกม (อนิเมชัน / UI-UX / ฟาร์ม) — คุยกันแล้วแตกเป็น 3 โปรเจกต์ย่อยเรียงกัน:

1. **ฟาร์มมีชีวิต** ← สเปกนี้
2. ออเดอร์รายวัน (บอร์ดออเดอร์สุ่มรายวัน ส่งพืชแลกรางวัลก้อน)
3. อาหารเพ็ท (พืช → อาหาร → เพ็ทกิน → buff ชั่วคราว)

เรียงแบบนี้เพราะข้อ 1 ไม่พึ่งใคร ส่วนข้อ 2–3 ต่างก็ "กินผลผลิตจากฟาร์ม" เหมือนกัน — ทำข้อ 1 ให้นิ่งก่อน
อีกสองอันจะออกแบบตัวเลขง่ายกว่า · (backlog ฟาร์มเดิม 4 ข้อใน ROADMAP: ปรุงยา/อาหารเพ็ท/โรงงาน/ออเดอร์
— user เลือกออเดอร์+อาหารเพ็ท ปรุงยาเลื่อนไปก่อน โรงงานตัดทิ้งเพราะเป็น idle ซ้อน idle)

**ปัญหาที่สเปกนี้แก้:** ฟาร์มตอนนี้ปลูกแล้วรอเฉยๆ พืชเป็นอีโมจิตัวเดิมตั้งแต่วันปลูกจนวันเก็บ
(มีแค่แถบ % กับการ scale 0.55→1.0) เก็บเกี่ยวกับขายก็ได้แค่ toast ตัวหนังสือ — ไม่มีอะไรบอกว่า "มีอะไรเกิดขึ้น"

## ขอบเขต

**ทำ**

1. พืชเปลี่ยนภาพตามระยะการโต (🌱 → 🌿 → ผลจริง)
2. แปลงปลูกเป็นฉากดิน/ฟ้า (แบบ "A+" ที่ user เลือกจาก mockup — โครงข้อมูลเดิม เปลี่ยนแค่พื้นหลัง)
3. เก็บเกี่ยว → ผลผลิตลอยจากแปลงเข้ากล่องผลผลิต 🧺
4. ขาย → เหรียญพุ่งไปที่ตัวนับเหรียญ + ตัวเลขนับขึ้น (ต้องเพิ่มตัวนับเหรียญบนหัวการ์ดฟาร์มก่อน)

**ไม่ทำ — จงใจ**

- ไม่แตะกลไกเกมแม้แต่นิดเดียว: เวลาโต ราคาเมล็ด ราคาขาย จำนวนผลผลิต เหรียญ เท่าเดิมทุกตัว
- ไม่มีรดน้ำ/ปุ๋ย/คุณภาพผลผลิต (เสนอไปแล้ว user ตอบว่า "รอพืชโตเฉยๆ")
- ไม่มีเอฟเฟกต์ตอนปลูก และไม่มีเอฟเฟกต์ตอนข้ามระยะ (user เลือกเฉพาะเก็บเกี่ยว+ขาย)
- ไม่มีกลางวัน/กลางคืน ไม่มีสภาพอากาศ
- ไม่แตะ `useFarm.js`, Firestore, `userSchema.js`, `firestore.rules`

**เลื่อนไปรอบหลัง (บันทึกไว้ ไม่ใช่ของรอบนี้)**

- ตั้งชื่อพืชใหม่ / รีไรท์ข้อความในฟาร์ม (user เกริ่นไว้ตอนเลือกแบบ)
- ฟาร์มเป็นฉากเดียวทั้งผืน (ตัวเลือก C ตอน brainstorm — งานใหญ่ ต้องคิดเลย์เอาต์ใหม่ตอนปลด 9–12 แปลง)

## ดีไซน์

### 1. ระยะการโต — ตรรกะบริสุทธิ์ใน `data/crops.js`

เพิ่มของ 3 อย่าง ไว้ที่เดียวกับข้อมูลพืช:

```js
/** ระยะกลางที่ใช้ร่วมกันทุกพืช (ต้นอ่อน → ต้นโต) */
export const DEFAULT_STAGES = ['🌱', '🌿']

/** สัดส่วนความคืบหน้าที่เปลี่ยนระยะ */
export const STAGE_CUTS = [0.33, 0.70]

/**
 * อีโมจิที่ควรแสดงตามความคืบหน้า (0..1)
 *   < 0.33 → ระยะ 1 · 0.33–0.70 → ระยะ 2 · ≥ 0.70 → อีโมจิพืชจริง
 * พืชที่ใส่ `stages` ไว้ในข้อมูล จะใช้ค่านั้นแทน DEFAULT_STAGES
 */
export function stageEmoji(crop, progress) { … }
```

**พฤติกรรมที่ต้องเป็นจริง (= เคสเทส)**

| อินพุต | ผลลัพธ์ |
|---|---|
| `progress` 0 / 0.32 | ระยะ 1 (`🌱`) |
| `progress` 0.33 / 0.69 | ระยะ 2 (`🌿`) — ขอบเขตนับเข้าระยะถัดไป |
| `progress` 0.70 / 1 / 5 (เกิน) | อีโมจิพืชจริง |
| `progress` ติดลบ / `NaN` / `undefined` | ระยะ 1 (ไม่พัง) |
| `crop` เป็น `null` | คืน `''` (ไม่พัง) |
| พืชที่มี `stages: ['🌱','🌲']` | ใช้ `🌲` เป็นระยะ 2 |
| พืชที่มี `stages` ยาวไม่ครบ/ว่าง | fallback กลับ `DEFAULT_STAGES` |

**การใช้ `stages` override:** ใส่เฉพาะพืชที่ระยะกลางร่วมดูแปลก — รอบแรกตั้งให้
`moneytree` (ต้นไม้เงินตรา) = `['🌱','🌲']` และ `lotus` (บัวหลวง) = `['🌱','🍃']` เท่านั้น
พืชที่เหลือใช้ค่าเริ่มต้น (ถ้าเห็นตัวไหนดูแปลกตอนเทสจอจริง ค่อยเติมทีหลังได้ — เป็นข้อมูล ไม่ใช่โค้ด)

**ข้อจำกัดที่ตรวจแล้ว:** ไฟล์ `public/emoji/fluent/` มี `🌱` (1f331) `🌿` (1f33f) `🌲` (1f332) `🍃` (1f343) ครบแล้ว
→ **ไม่ต้องรัน `scripts/fetch-fluent.mjs`** (สคริปต์นั้นต้องต่อเน็ตดึงจาก GitHub) ถ้าอนาคตเพิ่ม override เป็นอีโมจิตัวใหม่
ต้องรันสคริปต์ก่อน ไม่งั้น `<Emoji>` จะ fallback ไปใช้ฟอนต์เครื่อง (หน้าตาไม่ตรงกันแต่ละเครื่อง ไม่ถึงกับพัง)

`FarmGrid.vue` เรียก `stageEmoji(stat(plot).crop, stat(plot).progress)` แทนการอ่าน `crop.emoji` ตรงๆ
ส่วนการ scale ตาม progress ที่มีอยู่แล้ว (`emojiStyle`) คงไว้เหมือนเดิม — ระยะเปลี่ยนภาพ scale เปลี่ยนขนาด ทำงานคู่กัน

### 2. หน้าตาแปลง "A+" — CSS ล้วนใน `FarmGrid.vue`

- `.plot` เปลี่ยนพื้นหลังเป็นไล่สี **ฟ้า → เขียวอ่อน → ดินน้ำตาล** โดยมีเส้นขอบฟ้าประมาณกลางแปลง
  (`linear-gradient` หลาย stop + จุดดินจางๆ ด้วย `radial-gradient` ผ่าน `::before`) → ต้นไม้ดูเหมือนยืนบนดิน
- ชื่อพืช/เวลาที่เหลือ เปลี่ยนเป็นตัวขาว + `text-shadow` เพราะพื้นเข้มขึ้น · แถบ % พื้นหลังเปลี่ยนเป็นขาวโปร่ง
- **ตำแหน่งทุกอย่างคงเดิม**: แถบ %, ข้อความนับถอยหลัง, ป้าย "พร้อม!", ปุ่มเก็บเกี่ยว, ปุ่ม ＋ ปลูก
- แปลงว่าง (`.plot.empty`) คงเป็นกรอบประจุดจางๆ แบบเดิม ไม่ต้องมีฉาก (จะได้ต่างจากแปลงที่ปลูกแล้วชัดๆ)
- สถานะพร้อมเก็บ (`.plot.ready` + `plotGlow` + `ripeBob`) คงของเดิมทั้งหมด แค่ปรับสีให้เข้ากับพื้นใหม่
- คง `@media (prefers-reduced-motion: reduce)` ที่มีอยู่ให้ครบเหมือนเดิม
- **ลบ CSS ที่ตายแล้ว** ในไฟล์นี้: `.plot-actions` `.plot-mini` `.plot-fertcost` (ไม่มี template ไหนใช้ —
  เหลือจากระบบรดน้ำ/ปุ๋ยที่ไม่เคยมีจริง) · ตรวจก่อนลบด้วย `grep -rn "plot-mini\|plot-actions\|plot-fertcost" src/`

### 3. ชั้นเอฟเฟกต์ — โมดูลใหม่ `utils/farmfx.js`

โมดูล JS ล้วน (ไม่พึ่ง Vue) หน้าที่เดียว: **ยิงของจากสี่เหลี่ยม A ไปสี่เหลี่ยม B**

```js
export function flyTo({ emoji, from, to, count = 1, onArrive })   // from/to = DOMRect
```

**ข้อบังคับ (แต่ละข้อมีเหตุผลจากบั๊กที่เคยเจอจริง)**

- **ชั้นเอฟเฟกต์ต้องแปะไว้ที่ `document.body`** ไม่ใช่ใน component — เพราะ `#main-content` เป็น `position:fixed`
  = สร้าง stacking context ของที่อยู่ข้างในสู้ `#bottom-nav` ไม่ได้ ต่อให้ z-index สูงแค่ไหน
  (CLAUDE.md ข้อ 6 · บั๊กนี้วนกลับมา ≥5 รอบแล้ว) · ชั้นนี้ต้อง `pointer-events:none` และ `aria-hidden`
- ขับด้วย **WAAPI** เปลี่ยนเฉพาะ `transform` / `opacity` (หลักการเดียวกับ `battlefx.js` ที่ใช้ปิดเคส
  battle กระตุกบน iOS Safari สำเร็จ) — **แต่ไม่ import และไม่แก้ `battlefx.js`** เคสนั้นเพิ่งปิด อย่าไปแตะ
- ของที่ลอยเป็น element ชั่วคราวนอก Vue → Vue ไม่ re-render ระหว่างอนิเมชัน
- **`prefers-reduced-motion: reduce` → ข้ามอนิเมชันทั้งหมด** (ไม่สร้าง element เลย, เรียก `onArrive` ทันที)
  ผลลัพธ์ของเกมต้องถูกต้องเหมือนกันทุกกรณี
- เก็บกวาดเสมอ: `finish`/`cancel` แล้วต้อง `remove()` · ออกจากหน้าฟาร์ม (`onUnmounted`) ต้องยกเลิกของที่ค้าง
- ถ้า `from` หรือ `to` หาไม่เจอ (element หายไปแล้ว) → ไม่ทำอะไร ไม่ throw

**จุดเรียกใน `FarmGrid.vue`**

| จังหวะ | เอฟเฟกต์ |
|---|---|
| กดเก็บเกี่ยว | ผลผลิต 1 ชิ้นลอยจากแปลง → กล่องผลผลิต `.inv-head` · พอถึงแล้วกล่องเด้งสั้นๆ |
| กดขาย / ขายทั้งหมด | เหรียญ 🪙 พุ่งจากรายการที่ขาย → ชิปเหรียญบนหัวฟาร์ม (3–5 เหรียญ กระจายเวลาเล็กน้อย) พอถึงแล้วเลขนับขึ้น |

**ลำดับที่สำคัญ:** ต้อง `getBoundingClientRect()` ของต้นทาง **ก่อน** เรียก `farm.harvest()` / `farm.sell()`
เพราะ `patchUser` เป็น optimistic update — พอเรียกเสร็จ แปลงจะว่างและรายการผลผลิตจะหายจาก DOM ทันที
(กรณีขาย: จับ rect ตอนกดปุ่ม ก่อนเปิด `confirm` แล้วค่อยยิงหลังผู้ใช้ยืนยัน)

**กันภาพกะพริบ:** `<Emoji>` ตั้ง `loading="lazy"` ไว้ → ตอนพืชสลับระยะครั้งแรกรูปยังไม่ถูกโหลด จะวูบ
→ ตอน `onMounted` ของ `FarmGrid` ให้ preload รูประยะทั้งหมดที่เป็นไปได้ (`new Image().src = …`)
เหมือนที่เคยทำกับ projectile ของ battle (commit `b6a996c`)

### 4. ชิปเหรียญบนหัวฟาร์ม + เลขวิ่ง

เอฟเฟกต์ขายต้องมีปลายทาง แต่หน้าฟาร์มตอนนี้ **ไม่มีตัวเลขเหรียญเลย** (เห็นเฉพาะในโมดัลเลือกเมล็ดกับร้านค้าฟาร์ม)

- เพิ่มชิป `🪙 12,340` ที่ `.farm-head` ของ `FarmGrid.vue` — มีประโยชน์ในตัวอยู่แล้ว (รู้ว่าซื้อเมล็ดไหวไหมโดยไม่ต้องเปิดโมดัล)
  และเป็นเป้าให้เหรียญพุ่งเข้า
- composable ใหม่ `composables/useCountUp.js` (~30 บรรทัด): รับ ref ตัวเลข คืนตัวเลขที่ไล่ตามด้วย `requestAnimationFrame`
  · ค่ากระโดดลง (จ่ายเงินซื้อเมล็ด) ให้เปลี่ยนทันทีไม่ต้องวิ่ง — วิ่งเฉพาะตอนเพิ่ม เพื่อไม่ให้ดูเหมือนเงินไหลออกช้าๆ
  · เคารพ `prefers-reduced-motion` (เปลี่ยนทันที) · เคลียร์ rAF ตอน unmount
- ยังไม่เอาไปใช้ที่อื่นในรอบนี้ (หน้า Home ใช้ต่อได้ทีหลัง)

## ความเสี่ยง

| ความเสี่ยง | รับมือ |
|---|---|
| ของลอยโดน bottom-nav ทับ (บั๊กเก่าที่วนกลับมา 5 รอบ) | ชั้นเอฟเฟกต์อยู่ที่ `body` ไม่ใช่ในหน้า — ระบุเป็นข้อบังคับในสเปกแล้ว |
| มือถือเก่ากระตุก | WAAPI + `transform`/`opacity` เท่านั้น · ของลอยครั้งละไม่กี่ชิ้น (เหรียญ cap 5) · reduced-motion ปิดหมด |
| ตัวหนังสือขาวบนพื้นใหม่แล้วอ่านไม่ออก | `text-shadow` + เทสจอจริงกลางแดด · ห้ามฟอนต์ต่ำกว่า `.7rem` (กฎ CLAUDE.md) |
| พืชบางชนิดระยะกลางดูแปลก | `stages` override เป็นข้อมูลใน `crops.js` เติมทีหลังได้ ไม่ต้องแก้โค้ด |
