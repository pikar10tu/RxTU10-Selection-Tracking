## 2. ฐานสถาปัตยกรรม (P2a)

### 2.1 `unit.ps` — ที่เก็บ state ของพาสสีฟระหว่างไฟต์

วันนี้ state ถูกแปะเป็นฟิลด์ลอยบนตัวละคร: `unit.passiveUses` (ตัวนับ**เดียว**ที่ `revive`/`cheatDeath`/`saveAlly`
ใช้ร่วมกัน) และ `killer.atkStacks` · P2 เพิ่ม state อีก 6 กอง ⇒ ต้องมีที่อยู่ของมันเอง

```js
/** state ของพาสสีฟระหว่างไฟต์ — สร้างตอนถูกอ่านครั้งแรก (ไม่ต้องแตะ buildCombatant) */
const psOf = (u) => (u.ps || (u.ps = {}))
```

| คีย์ | ของใคร | ความหมาย |
|---|---|---|
| `uses` | เจ้าของสกิล | จำนวนครั้งที่ใช้ไปแล้ว (ย้ายมาจาก `passiveUses`) |
| `atkStacks` | เจ้าของสกิล | ชั้น `stackAtk` (ย้ายมาจาก `atkStacks`) |
| `rage` | เจ้าของสกิล | ชั้น `atkOnHit` ที่สะสมจากการโดนตี |
| `armor` | เจ้าของสกิล | สแตคเกราะที่เหลือ (`armorStack`) |
| `grit` | เจ้าของสกิล | หมัดที่แมวยังทนได้ + สถานะ atk +50% ระหว่างนั้น |
| `infect` | **เป้า** | `{ n, from }` — จำนวนชั้น + ตัวไวรัสที่แปะ |
| ~~`taunted`~~ | — | **ไม่ได้ใช้** — ลงมือจริงส่ง `forced` เป็นอาร์กิวเมนต์ของ `runOnHit` แทน (ไม่ต้องรีเซ็ตทุกรอบ) |

🔴 **ทำไมต้องเป็นก้อนเดียว ไม่ใช่ฟิลด์ลอย:** บั๊กที่แพงที่สุดของโปรเจกต์นี้คือบั๊กชื่อฟิลด์ชนกัน —
`kind` ของ event ชนกับ `kind` ของ `battleBeats` จนต้องเปลี่ยนไปใช้ `fxKind` (CLAUDE.md ข้อ 15)
การแปะฟิลด์ลอยเพิ่มอีก 6 กองบนตัวละครที่มี `atk`/`hp`/`uid`/`side`/… คือการเดินกลับเข้าบั๊กคลาสเดิม

### 2.2 hook ใหม่ 2 ตัว

| hook | เอนจินเรียกเมื่อไร | ใครใช้ |
|---|---|---|
| `setup` | **ก่อน `applyAuras` ทุกอย่าง** ตอนเริ่มไฟต์ | 🐭 `stealStats` |
| `onAnyDeath` | ทุกครั้งที่มีใครตายจริง (ผ่าน `onDeath` แล้วยังตาย) ยิงให้ทุกตัวที่ยังไม่ตาย**ฝั่งตรงข้ามของคนที่ตาย** | 🦖 `stackAtk` แบบใหม่ |

🔴 `setup` ต้องมาก่อน aura เพราะ `stealStats` เปลี่ยน `atk`/`maxHp` ของทั้งสองฝั่ง — ถ้ารันทีหลัง
`statsSnapshot` ที่ส่งให้รีเพลย์จะเป็นเลขก่อนขโมย แล้วตัวเลขบนการ์ดกับความเสียหายจริงจะไม่ตรงกัน

### 2.3 ช่อง `pierce` — ดาเมจที่ไม่ผ่านสายลด

`runOnHit()` คืน `res.pierce` เพิ่มอีกช่อง · `strike()` ในเอนจินหัก `res.dmg` (ผ่าน guardian → dodge →
ลดดาเมจ → หนาม) **แล้วค่อยหัก `res.pierce` ต่อ**

- ไม่ต้องแตะสายลดเลยแม้แต่บรรทัดเดียว ⇒ ของเดิมพังไม่ได้
- ยังอยู่ beat เดิม ไม่เพิ่มจังหวะ (กฎเหล็ก 🔒)
- หลอดเลือดยังตรง เพราะ `attack` event คิด `dmg` จาก `before - after` อยู่แล้ว
- ใช้กับ `infect` ตัวเดียวในรอบนี้ · **ห้ามเอาไปใช้กับกลไกอื่นโดยไม่แก้สเปก** — "ทะลุทุกอย่าง"
  เป็นสิทธิพิเศษที่ทำให้ไวรัสมีเหตุผลในการมีอยู่ ถ้าแจกให้ตัวอื่นด้วยมันจะกลายเป็นแค่ดาเมจเพิ่ม

### 2.4 กฎจังหวะของเพ็ทหลาย part

จาก §11 ของสเปกแม่ (วัดจากไฟต์จริง 400 ไฟต์: พาสสีฟ 20.57 event/ไฟต์ · กินเวลา 2,039ms จาก 20,032ms = 10.2%)

1. **หนึ่งเพ็ท × หนึ่ง hook = หนึ่งจังหวะ** ไม่ว่าจะยิงกี่ part — ใบสุดท้ายของก้อนถือเวลาหยุดคนเดียว
   ที่เหลือ 0ms (ทำซ้ำแพทเทิร์น `openQuiet`/`openGroup` ที่มีอยู่แล้ว **ห้ามเพิ่มชั้นเวลาใหม่**)
   ⇒ ถ้าปล่อยตามโค้ดวันนี้ เพ็ท 3 part จะได้ `SKILL_PAUSE` 200ms × 3 = หยุด 600ms ติดกัน
2. **คีย์ตัวดักซ้ำใน `battleBeats.js:160`** เปลี่ยนจาก `` `${e.uid}:${e.effect}` `` เป็นคีย์ที่มีลำดับ part
   ด้วย — ไม่งั้นเพ็ทที่มีสอง part ใช้ effect เดียวกัน part ที่สองจะถูกลดเป็น `skillQuiet` เงียบหายไป
3. **ลำดับใน `parts[]` = ลำดับบนจอ** — ล็อกด้วย `assert.deepEqual(effects, [...])` ในเทสเพ็ทหลาย part

### 2.5 ล้างของค้างจาก P1 (§10 ของสเปกแม่)

- `partWithEffect` ที่ `battlePassives.js:240` (guardian) และ `:315` (saveAlly) หาแบบ effect-first
  แล้วค่อยเช็ค hook → เปลี่ยนเป็น `partsAt(p, 'onHit').find(x => x.effect === 'guardian')`
- `partAt(p, 'onDeath')` ที่ `:291` เอา part แรกตัวเดียว → ใส่คอมเมนต์ว่าทำไม onDeath ถึงเป็น part เดียวโดยธรรมชาติ
- `upgradable.length >= 20` (`battlePassives.test.js:322-334`) เปลี่ยนหน่วยจาก "ตัวเพ็ท" เป็น "part" แล้ว → เขียนใหม่ให้นับ id ไม่ซ้ำ
- **`runOnHit` คืนฟิลด์ `absorber` ที่เอนจินไม่เคยอ่าน** (เจอตอนออกแบบ P2) → ลบทิ้ง

## 3. กลไกตัวคูณล้วน 8 ตัว (P2a)

ทุกตัวลงบน hook ที่มีอยู่แล้ว **ไม่แตะเอนจิน** เขียนเป็น pure function ใน `battlePassives.js` ตามแบบของเดิม

| effect | hook | สูตร | ค่าตั้งต้น | เพ็ท (P3) |
|---|---|---|---|---|
| `elementTrinity` | `aura` | ทีมมีครบ ✊✌️✋ → ทั้งทีม atk +`pct`% และ maxHp +`hpPct`% | 8 / 8 | 🦁 |
| `atkOnHit` | `onHit` | ทุกครั้งที่รับดาเมจ atk +`pct`% **ไม่มีเพดาน** | 3 ✅user | 🦍 |
| `berserk` | `onAttack` | ดาเมจ +`pct`% ต่อทุก **10% ของเลือดที่หายไป** (เลือด 40% = 6 ขั้น) | 6 | 🐗 |
| `giantSlayer` | `onAttack` | ดาเมจ +`pct`% ต่อทุก **10% ที่ maxHp เป้าสูงกว่า maxHp ตัวเอง** เพดาน `max`% | 5 · เพดาน 50 | 🦡 |
| `teamLifesteal` | `aura` | เพื่อนทุกตัว (รวมเจ้าของ) ฟื้นเลือด `pct`% ของดาเมจที่**ตัวเองตีได้** | 8 | 🦇 |
| `stealStats` | `setup` | ขโมย atk และ maxHp อย่างละ `pct`% จากศัตรู**ทุกตัว** — **ศัตรูเสียจริง** | 5 ✅user | 🐭 |
| `teamDamageReduction` | `aura` + `onHit` | ทั้งทีมรับดาเมจลด `pct`% · **เจ้าของเป็น 2 เท่า** | 10 (เจ้าของ 20) ✅user | 🐢 |
| `healOnAttack` | `onAttack` | เมื่อตี ฟื้นเลือดเพื่อนที่บอบช้ำสุด `pct`% ของดาเมจที่ทำได้ | 12 | 🦄 |

📌 **เลขในคอลัมน์ "ค่าตั้งต้น" คือค่าที่ใช้เดินได้จริงในเทส ไม่ใช่ค่าสุดท้าย** — ที่ไม่มี ✅user กำกับ
คือค่าที่ผมเสนอให้เทียบเคียงกับของเดิมในชั้นความหายากเดียวกัน · **P4 เป็นคนเคาะเลขจริงจาก sim**
ถ้า P4 จะเปลี่ยนต้องบอก user ไม่แก้เงียบ

**ประเด็นที่ต้องระวังรายตัว**

- `stealStats` ลด `maxHp` ของศัตรู ⇒ ต้องลด `hp` ปัจจุบันตามสัดส่วน ไม่งั้นศัตรูจะมีเลือดเกินหลอด
- `teamLifesteal` ฟื้นจากดาเมจ**ที่ทำได้จริง** (หลังลดทุกอย่าง) ไม่ใช่ดาเมจดิบ — ไม่งั้นเกราะฝั่งตรงข้ามยิ่งหนา ยิ่งดูดเยอะ
- `berserk` / `giantSlayer` คูณเข้า `res.atkMult` รวมกับ `execute`/`atkWhenFull` แบบ **คูณต่อกัน** ตามแบบเดิม
- `teamDamageReduction` ซ้อนกับ `damageReduction` ของตัวเอง: หักเป็นทอด (`dmg × (1-a) × (1-b)`) ไม่ใช่บวก % กัน

## 4. ตัวยาก 3 ตัว (P2b)

### 4.1 `infect` — เชื้อลุกลาม

| เรื่อง | กติกา |
|---|---|
| แปะ | ไวรัสตีใคร เป้านั้น `ps.infect.n += 1` · **เพดาน 5 ชั้น** · ขึ้นจากหมัดไวรัสเท่านั้น |
| ระเบิด | เป้าที่ติดเชื้อถูกตีโดย**ใครก็ได้ในทีมไวรัส** (รวมไวรัสเอง) → `pierce += pct% × atk ไวรัส × n` |
| ไม่หาย | เชื้อไม่ลดตอนระเบิด |
| ทะลุ | ไปทางช่อง `pierce` ⇒ ไม่โดน dodge / damageReduction / teamDamageReduction / guardian / armorStack |
| ไวรัสตาย | เชื้อที่แปะไว้**ยังทำงานต่อ** — อ่าน `atk` จาก object ของไวรัสที่ตายแล้วได้ตรงๆ ไม่ต้อง freeze ค่า |
| ตัวติดเชื้อล้ม | โยนชั้นทั้งหมดไปศัตรูตัวอื่น **สุ่ม 1 ตัว** ด้วย `rand` ของเอนจิน (deterministic) · ยึดเพดาน 5 |

ค่าตั้งต้น: `pct` = 15 ต่อชั้น · เพดาน 5 ชั้น ✅user

✅ **เคาะเพิ่ม 4 ก.ย. (สเปกเดิมไม่ได้ตอบ): ไวรัสสองตัวในทีมเดียวกัน — "ตัวแรกที่แปะเป็นเจ้าของเชื้อ"**
`from` ถูกตั้งครั้งเดียวตอนเป้าสะอาดกลายเป็นติดเชื้อ แล้วไม่เปลี่ยนอีกจนกว่าเชื้อจะหมด ·
ไวรัสตัวที่สองเติมชั้นเข้ากองเดียวกันได้ แต่ไม่ยึดความเป็นเจ้าของ
**เหตุผล:** ดาเมจระเบิดคิดจาก `from.atk` ⇒ ถ้าเจ้าของเปลี่ยนกลางไฟต์ ความแรงของเชื้อจะเปลี่ยนโดยไม่มีสัญญาณอะไรบอกผู้เล่นเลย ·
และทำให้สองสาขา (ยังไม่ชนเพดาน / ชนเพดานแล้ว) ตอบเหมือนกัน · การส่งต่อเชื้อตอนตาย (§4.1 แถวสุดท้าย) พา `from` ไปด้วย จึงยังสอดคล้องกัน

### 4.2 `taunt` — ตีอกท้าชน

- ต้นรอบ: ศัตรูทุกตัวที่ออกหมัดในรอบนั้นต้องตีมาที่กอริลลา
- ระหว่างถูกตีจากผลบังคับ กอริลลาลดดาเมจ `pct`% (ค่าตั้งต้น 25) — **เฉพาะหมัดที่ถูกดึงมา** ไม่ใช่ตลอดเวลา
  ⇒ ต้องแปะ flag มากับผลของการเลือกเป้า ห้ามให้ `runOnHit` เดาเอง
- 🔴 **ลำดับการเลือกเป้า (ต้องเป็นเทส):** `taunt` > `targetLowest` (🦅) > สุ่มปกติ
- 🔴 `guardian` ทำงาน**หลัง**เลือกเป้าเสร็จแล้ว และไม่รับแทนตัวเอง
  ✅ **user เคาะ 4 ก.ย.: ถ้าเป้าคือกอริลลาและบากุอยู่ในทีม บากุ*รับแทนได้*ตามกฎปกติ — ตั้งใจให้เป็นคอมโบ**
  (กอริลลายืนได้นานขึ้น + ยังได้ดาเมจจากผลอื่น ⇒ เกมเพลย์หลากหลายขึ้น)
  ⚠️ ห้าม "แก้" ให้บากุเลิกรับแทนเป้าที่ถูก taunt — นั่นคือพฤติกรรมที่ตั้งใจ ไม่ใช่บั๊ก
- กอริลลา 2 ตัวในทีมเดียว: **ช่องซ้ายสุดชนะ** (ต้อง deterministic ไม่งั้นรีเพลย์ไม่ตรงกับผลจริง)

**นี่คือจุดเดียวใน P2 ที่แตะ `battleEngine.js` จริง** — `pick()` กลายเป็นฟังก์ชันเลือกเป้าที่มีลำดับ

### 4.3 `armorStack` — เกราะปฐพี

- เริ่มไฟต์ได้ `ps.armor = 2` สแตค
- โดนหมัด → กิน 1 สแตค **กันหมัดนั้นทั้งหมด** (`res.dmg = 0` ไม่ใช่โล่ที่มีค่าเลือด)
  แล้ว**สะท้อน `pct`% ของดาเมจนั้นใส่ศัตรูทั้งหมด** (ค่าตั้งต้น 80 ✅user)
- ดาเมจสะท้อน **หักลดตามปกติ** (โดน dodge/DR/เกราะฝั่งตรงข้ามได้) — มีแค่ `infect` ที่ทะลุ
- หมดสแตคแล้วรับดาเมจปกติ · ไม่มีการเติมระหว่างไฟต์
- 🔴 กันหมัดได้ **ก่อน** `pierce` ⇒ ดาเมจเชื้อยังเข้าแม้เกราะจะกันหมัดหลักไว้หมด (ตั้งใจ)

## 5. ขยายของเดิม 8 จุด (P2c)

| เพ็ท (id) | เดิม | ใหม่ | ระวัง |
|---|---|---|---|

## 6. ภาษาการเล่าเรื่องของพาสสีฟในรีเพลย์ (P2c)

**ปัญหาที่วัดได้:** พาสสีฟทำงาน 20.57 ครั้ง/ไฟต์ แต่ **15.43 ครั้ง (75%) เงียบสนิท** — ประกาศแค่ครั้งแรก
ของสกิลนั้น หลังจากนั้นมีแค่ประกายวูบ · และชิปที่ขึ้นบอกแค่**ชื่อ**สกิล ไม่ได้บอกว่าเกิดอะไร

(ตัวเลข 20.57 / 15.43 มาจากการวัดไฟต์จริง 400 ไฟต์ · ส่วนการเทียบ "เล่าได้กี่จังหวะ" มาจาก mockup
ที่เขียนฉากขึ้นมาเอง 7 จังหวะเพื่อให้ user เห็นภาพ — เป็นภาพประกอบการตัดสินใจ ไม่ใช่ค่าที่วัดจากเกม)

### 6.1 ชิปเต็ม — เพิ่มบรรทัดผล

ชิปของ `skill` / `openGroup` เป็น **2 บรรทัด**: บรรทัดบน `ไอคอน + ชื่อสกิล` · บรรทัดล่าง **ข้อความผลพร้อมเลขจริง**
จาก `effectText(passive, lv, { effect: part.effect })`

⇒ ออปชัน `effect` ที่ P1 ใส่ไว้แล้วแต่ยังไม่มีใครใช้ **ได้ใช้จริงที่นี่** · วันนี้มันคืน `short` เดียวของทั้งตัว
P3 จะเติม `short` รายพาร์ทเข้ามาโดยไม่ต้องแก้จุดเรียกอีก

### 6.2 มินิชิป — ครั้งซ้ำต้องไม่เงียบ

`skillQuiet` (15.43 ครั้ง/ไฟต์) ได้ชิปเล็กทรงกลม **ไอคอนของผล + เลข** ไม่มีชื่อสกิล:
`🧱 −12%` · `🦠 ×2` · `🔥 +18%` · `💨 หลบ`

- **0ms** — เกาะไปกับจังหวะที่มีอยู่แล้ว ไม่ขอเวลาเพิ่มแม้แต่มิลลิวินาทีเดียว
- อายุ ~420ms แล้วจางเอง (ทับ beat ถัดไปได้ เหมือน `CHIP_OUT_MS` ของเดิม)
- ไอคอนมาจาก `STATUS_ICON` ที่มีอยู่แล้ว — effect ใหม่ทุกตัวต้องเพิ่มไอคอนของตัวเองในคอมมิตเดียวกัน

### 6.3 ผูกเหตุกับผล — เลขดาเมจพกไอคอนต้นเหตุ

`attack` event เพิ่มฟิลด์ `causes: string[]` = รายชื่อ effect ที่ทำให้เลขนี้เปลี่ยน (เอนจินเก็บจากผลของ
`runOnAttack`/`runOnHit`) · รีเพลย์เอาไอคอนต่อท้ายเลข **สูงสุด 2 ตัว** เช่น `1,090 🧱` · `1,860 🔥`

⇒ ผู้เล่นเห็น "ทำไม" ไม่ใช่แค่ "มีอะไรวูบ" · **ดาเมจทะลุแยกเป็นเลขของตัวเอง** (สีม่วง `🦠 620 ทะลุ`)
ไม่รวมเข้ากับเลขหมัดปกติ — ถ้ารวมจะอธิบายไม่ได้เลยว่าทำไมเกราะไม่กัน

### 6.4 ป้ายสะสมบนการ์ด — สถานะที่ "ค้างอยู่"

ป้ายที่มี**ตัวเลข** แสดงค่าใน `ps` ที่กำลังค้าง: `🦠 ×3` (เชื้อ) · `🔥 ×6` (ขั้น berserk) · `🛡️ ▮▮` (สแตคเกราะ) · `⬆️ ×2` (ชั้น atk)

- อยู่**คนละแถว**กับป้ายบัฟเดิม (`STATUS_ICON` + `STATUS_MAX = 3`) เพราะคนละความหมาย:
  ป้ายเดิม = "ได้บัฟอะไรอยู่" · ป้ายใหม่ = "สะสมอะไรไว้เท่าไร"
- เพดานของตัวเอง 3 ใบ · **ต้องวัดใหม่ใน P2c** ว่าชนเพดานบ่อยแค่ไหน (ของเดิมวัดไว้ เฉลี่ย 1.09 ใบ ชน 4.7%)
- 🔴 นี่คือของที่ `infect` ขาดไม่ได้ — สเปกแม่ §4.1 เขียนไว้แล้วว่า "ต้องโผล่เป็นตัวเลขชั้น ไม่ใช่ป้ายเฉยๆ"

### 6.5 ข้อจำกัดที่ทั้งหมดต้องเคารพ

- 🔒 **ห้ามเพิ่มเวลาไฟต์** — พาสสีฟกินไปแล้ว 10.2% ของไฟต์ · ของใหม่ทุกอย่างในข้อ 6 เป็น 0ms
- ชิปโผล่ติดกันได้สูงสุด **5 ใบ**ในจังหวะเดียว (วัดแล้ว) — ดีไซน์ต้องไม่พังตอนขึ้นพร้อมกันหลายใบ
- ห้ามใช้ป้ายลอย (`fx.banner`) — พูลมีแค่ 2 ช่อง เคยถูกยึดไปโผล่ผิดการ์ดมาแล้ว ใช้ชิปที่เกาะการ์ดเท่านั้น

## 7.4 หนี้ที่ P2a ทิ้งไว้ให้ P2b/P2c ใช้คืน (บันทึก 4 ก.ย. 2026)

P2a จบด้วย **2,587 ไฟต์เหมือน base ทุกไบต์** และเทส 1,027 ตัวผ่านหมด แต่รีวิวรวมทั้ง branch
เจอของที่ "ตายอยู่วันนี้เพราะยังไม่มีเพ็ทถือ" ไว้ 6 ข้อ — ทุกข้อจะมีชีวิตขึ้นมาทันทีที่ P3 แจกกลไกให้เพ็ท

### ต้องทำใน P2b

1. 🔴 **เทส end-to-end ว่าดาเมจเชื้อทะลุจริง** — P2a เปิดช่อง `pierce` ไว้แต่พิสูจน์ไม่ได้เพราะไม่มีตัวผลิตค่า
   (เทสที่เขียนตอนนั้นกลายเป็นการทดสอบตัวเอง เลยลบทิ้ง) · P2b ต้องยิงผ่าน `simulateBattle` จริง
   แล้วยืนยันว่าดาเมจเชื้อไม่ถูกหักโดย dodge / damageReduction / teamDamageReduction / guardian / armorStack
2. 🔴 **เคาะว่า `atkOnHit` ควรสะสมไหมเมื่อหมัดถูกหลบหรือถูกกันหมด** — วันนี้สะสมทุกกรณี
   `armorStack` ของ P2b คือกลไกที่กันทั้งหมัด จึงเป็นรอบที่ต้องตอบ
3. ⚠️ **`teamLifesteal` ต้องมีการ์ด `attacker.hp > 0`** — ตอนนี้ถ้าผู้ตีโดนหนามตายกลางบีต
   แล้วมี sub-hit ต่อ (cleave/multiStrike) มันจะดูดเลือดตัวเองกลับมาเกิน 0 **โดยไม่ผ่าน `runOnDeath` เลย**
   = ฟื้นคืนชีพโดยไม่เคยตายอย่างเป็นทางการ · ยังไม่มีเพ็ทถือ จึงยังไม่เกิด

### ต้องทำใน P2c

4. 🔴 **แก้ `runOnKill` ที่ถูกเรียกสองครั้งต่อการฆ่าหนึ่งครั้ง** (`battleEngine.js` — ในลูป `while` หนึ่งครั้ง
   แล้ว `if (killed)` ท้ายลูปอีกครั้ง) ⇒ 🦖 ทีเร็กซ์ได้ 2 ชั้นต่อการล้ม 1 ตัว
   ⚠️ **ห้ามแก้ด้วยการลบบรรทัดท้ายทิ้งเฉยๆ** — เงื่อนไข `while` มี `alive(foes).length` อยู่ด้วย แปลว่า
   **การฆ่าครั้งสุดท้ายของไฟต์ไม่เคยเข้าลูป** บรรทัดท้ายจึงเป็นตัวเดียวที่ยิงให้มัน · ลบแล้วหมัดปิดเกม
   จะไม่ได้ชั้นเลย และ `killChain` ของ 👹 จะหาย event ตอนเก็บตัวสุดท้าย
   ⇒ ต้องรวมสองจุดเป็นการเรียกครั้งเดียวที่ครอบทั้งสองกรณี **และมีเทสเจาะจงที่ "หมัดที่ปิดไฟต์"**
   ⇒ แก้เสร็จแล้ว beat ที่ต่างจาก base 89 ไฟต์ควรกลายเป็น 0 (ตอนนี้ `battle-differential` รายงานเลขนี้
   เป็นบรรทัดข้อมูล ไม่นับเป็นเงื่อนไขผ่าน — พอแก้แล้วให้เลื่อนขึ้นมาเป็นเงื่อนไขผ่านได้)
5. ⚠️ **เทสระดับ `simulateBattle` ของ hook `onAnyDeath`** — P2a เทสแค่ระดับฟังก์ชัน pure

### ต้องระวังตอน P3 แจกกลไกให้เพ็ท

6. ⚠️ **ลำดับ part ใน `parts[]` ของ hook `onHit` มีผลจริง** — ลูปเดินตามลำดับข้อมูล ไม่ได้บังคับให้ `dodge`
   มาก่อน ⇒ เพ็ทที่เขียน `[{onHit, damageReduction}, {onHit, dodge}]` จะเด้งป้าย "ลดดาเมจ 12" บนหมัดที่
   สุดท้ายถูกหลบทั้งหมัด · ถ้า P3 จะมีเพ็ทแบบนี้ ต้องยก `dodge` ออกมาทำก่อนลูป หรือมีเทสบังคับลำดับข้อมูล
7. ⚠️ **`teamLifesteal` อาจต้องเข้า `OUT_OF_GROUP_EFFECTS`** — ถ้าเพ็ทตัวเดียวมีทั้ง `healOnAttack`
   และ `teamLifesteal` ทั้งคู่ยิงบน uid เดียวกันติดกัน กฎจังหวะจะปิดเสียงใบแรก (ป้าย `healOnAttack` หาย)
   เป็นอาการเดียวกับที่ `duoRegen` ต้องถูกกันออกมา
8. ⚠️ **ป้าย `elementTrinity` โกหกได้** — `buffSources` เป็น static ก่อนไฟต์ จึงประเมินเงื่อนไข "ครบ 3 สาย"
   ไม่ได้ ⇒ ทีมที่ขาดสายก็ยังเห็นป้าย 🔺 · และ `liveBuffs` จะไม่โชว์ตัวนับชั้นของ `atkOnHit` เพราะมันไม่มี
   `value.max` ให้คำนวณเพดาน

## 7.5 หนี้ที่ P2b ทิ้งไว้ให้ P2c/P3/P4 (บันทึก 5 ก.ย. 2026)

P2b จบด้วย **2,587 ไฟต์เหมือน base ทุกไบต์** (kind และเวลารวมก็ไม่ขยับ) · 1,054 เทสผ่าน
รีวิวรวมทั้ง branch ชี้ของที่ต้องไปจบใน P2c ไว้ดังนี้

### P2c ต้องตัดสินใจ ไม่ใช่แค่ลงมือ

1. 🔴 **แก้ `runOnKill` ที่ยิงซ้ำ (หนี้ §7.4 ข้อ 4) ตอนนี้พันกับดาเมจสะท้อนแล้ว** — ทุกวันนี้การฆ่าด้วย
   ก้อนสะท้อนของ `armorStack` ไปถึง `runOnAnyDeath` แต่**ไม่ถึง `runOnKill`** (เอนจินทิ้งค่าที่ `strike()` คืน)
   ⇒ ตอนรวมสองจุดเป็นการเรียกครั้งเดียว ต้องตอบให้ชัดว่า "ฆ่าด้วยการสะท้อน" นับเป็นการฆ่าไหม
   (กันไม่ให้ `killChain` เพิ่ม beat = ถูกแล้ว · แต่ `stackAtk` ควรได้หรือไม่ ต้องเคาะ)
2. 🔴 **การจัดชั้นเวลาผิดเมื่อหมัดลูกเป็นคนปิดไฟต์** — `battleBeats` เลือก `finishAt` จาก attack ตัวสุดท้าย
   ที่**ไม่ใช่** `sub` และให้ `sub` ทุกใบเวลา 0 ⇒ ก้อนสะท้อนที่ปิดเกมถูกเล่าเป็น 0ms ส่วนหมัดหลักที่กันไว้
   จนดาเมจเป็น 0 กลับได้บีตปิดเกม ×4 · มีมาก่อน P2b (cleave ก็ทำได้) แต่ `armorStack` ทำให้เจอบ่อยขึ้นมาก
3. 🟡 **event ของก้อนสะท้อนถูก log ก่อนหมัดที่เป็นต้นเหตุ** ⇒ §6.3 ที่จะผูก "เหตุ→ผล" จะเล่ากลับหลัง
   ถ้าไม่เรียงใหม่หรือชดเชยตอนเรนเดอร์
4. 🟡 **`fxKind: 'debuff'` ยังไม่มีตัวเรนเดอร์** — ทั้ง `infect` (แปะ) และ `infectSpread` (ย้าย) ตกไปที่
   `default: break` ใน `firePassiveFx` ⇒ ได้ชิปแต่ไม่มีเอฟเฟกต์ · §6.2/§6.4 คือที่ของมัน
5. 🟡 **จำนวนชิปต่อบีตอาจทะลุเพดานที่วัดไว้** — เกราะทำงานครั้งเดียวยิงสะท้อนใส่ศัตรู*ทุกตัว* แต่ละก้อน
   ไปจุดชนวนเชื้อบนเป้านั้นอีก · `multiStrike` คูณจำนวนก้อนในบีตเดียว ⇒ อาจได้ `attack` ลูก 8 ใบ
   + ชิป `infectBurst` 4 ใบในบีตเดียว เทียบกับเพดานที่ §6.5 วัดไว้ที่ 5 ใบ

### ✅ เคาะแล้ว 5 ก.ย. — สองข้อที่ P2c ต้องใช้

- **ฆ่าด้วยก้อนสะท้อนของ `armorStack` ไม่นับเป็น "ฆ่า" (ไม่เข้า `onKill`)** — onKill ที่เหลือหลัง P2c
  มีแค่ `killChain` ซึ่งเพิ่ม beat จริง (ผิดกฎเหล็ก 🔒) · 🦖 ทีเร็กซ์ย้ายไป `onAnyDeath` ใน P2c อยู่แล้ว
  จึงได้ชั้นจากการตายทุกแบบโดยไม่ต้องพึ่ง onKill
- **หมัดลูกที่ปิดไฟต์: ทั้งก้อนถือเวลาปิดเกมร่วมกัน ใบสุดท้ายถือเวลาคนเดียว** (แพทเทิร์นเดียวกับ
  `openQuiet`/`openGroup` ที่ P2a วางไว้) ⇒ `finishAt` นับหมัดลูกด้วย · ใบอื่นในบีตนั้นได้ 0ms แต่ยังมี weight ของตัวเอง
  ⇒ **ไม่เพิ่ม beat** และคนดูเห็นหมัดที่ปิดเกมจริงๆ แทนที่จะเห็นหมัดที่ถูกกันจนดาเมจเป็น 0 กินเวลา ×4

### P4 ต้องรู้ตอนจูนเลข

6. 🟡 **`forced` แปลว่า "มีตัวท้าชนอยู่" ไม่ใช่ "หมัดนี้ถูกดึงมา"** — ในสถานการณ์ 1v1 หรือตอนกอริลลา
   เป็นตัวสุดท้ายที่เหลือ ส่วนลด 25% จะติดทุกหมัด ทั้งที่ไม่มีอะไรถูกเปลี่ยนเป้า · เป็นพฤติกรรมที่รับได้
   (จะรู้ได้ยังไงว่า "ถ้าไม่บังคับแล้วสุ่มจะเลือกใคร") แต่โมเดลบาลานซ์บนกระดาษต้องรู้ว่ามันเป็น DR ถาวรในเคสนั้น

### แก้ในสเปกเองแล้ว

## 7.6 หนี้ที่ P2c-1 ทิ้งไว้ให้ P2c-2/P3/P4 (บันทึก 6 ก.ย. 2026)

P2c-1 จบด้วย **1,080 เทสผ่าน · build ผ่าน** · เพ็ท 8 ตัวแยก commit ละตัวและผ่านด่าน isolation รายตัวครบ
รีวิวใหญ่ทั้ง branch ไม่มี Critical · Important 2 ข้อแก้จบแล้วทั้งคู่ (บีตปิดเกม · `statsAfter` ของแมว)
ของที่ **ตั้งใจไม่ทำในเฟสนี้** และคนทำเฟสหน้าต้องรู้:

1. 🔴 **การตายเงียบ — ดาเมจสามสายลด `hp` ตรงๆ โดยไม่ผ่าน pipeline `onDeath`/`onAnyDeath`**

   **ฟีนิกซ์ไม่คืนชีพ** · จินนี่ช่วยเพื่อนไม่ทัน · แมวไม่ได้ใช้ `cheatDeath`
   วัดจริงตอนปิดเฟส: **614/2,587 ไฟต์มีการตายที่ log ไม่เคยบันทึก**
   บาฮามุท 150% (เลขใหม่ของเฟสนี้) ทำให้ชนบ่อยขึ้นมากเมื่อพลังต่างกันมาก —
   ทีม `[bahamut g5, trex g3]` เจอ common g0 ⇒ **ทีเร็กซ์ได้ 0 ชั้นใน 50/50 ไฟต์**
   และเกิดไฟต์ที่ **ไม่มี attack event เลย** ได้ (`log = [aoeOpener, end]`, `rounds: 0`) 50/50 ไฟต์
   ⚠️ คู่เกรดเท่ากันไม่เจอเลย (0/486) ⇒ ไม่ใช่เรื่องด่วน แต่ต้องทำ **ก่อน P3 เพิ่มเพ็ทที่พึ่ง onDeath**
   ผลข้างเคียงที่ตามมา: กติกา `finishAt` ใน `battleBeats.js` อนุมาน "ใบไหนปิดไฟต์" จาก log ล้วน
   จึงมีรูปแบบแคบที่ยังอนุมานไม่ได้ (วัดแล้ว 0/2,587) — **ปิดสนิทได้ก็ต่อเมื่อเอนจิน log การตายพวกนี้**

   ### ✅ ผู้ใช้เคาะแล้ว 6 ก.ย. 2026 — กติกาที่เฟสหน้าต้องทำตาม

   **หลัก: การตายทุกทางต้องนับเป็นการตาย · ใครสร้างดาเมจ คนนั้นคือผู้ฆ่า · การเปลี่ยนทางเดินของดาเมจไม่เปลี่ยนเจ้าของ**

   | ทางที่ตาย | ผู้ฆ่า | เหตุผล |
   |---|---|---|
   | หนาม | **เจ้าของหนาม** | สกิลเป็นคนสร้างดาเมจ |
   | ก้อนสะท้อนเกราะ | **เจ้าของเกราะ** | เหมือนกัน |
   | หมัดสวนฟีนิกซ์ | ฟีนิกซ์ | เป็นแบบนี้อยู่แล้ว ไม่ต้องแก้ |

   ผลที่ตามมาโดยตรงและถือว่าถูกต้องแล้ว ไม่ต้องถามซ้ำ: ฟีนิกซ์ที่ตายเพราะหนาม **สวนใส่เจ้าของหนาม**
   (มันคือผู้ฆ่าตามนิยามนี้จริง) · ฟีนิกซ์/แมว/จินนี่ ต้องได้ใช้พาสสีฟกันตายทุกทางที่ตาย · ทีเร็กซ์ได้ชั้นทุกการล้ม

   🔴 **ข้อบังคับตอนลงมือ (เขียนไว้ก่อนเจอตอนเทสแดง):** หนามและก้อนสะท้อนทำงาน**ข้างใน `strike()` ที่ยังไม่จบ**
   ⇒ พอการตายถูกนับ `onKill` ของเจ้าของสกิลจะยิงกลางหมัดของคนอื่น และถ้าเจ้าของสกิลถือ `killChain`
   จะได้หมัดเพิ่มซ้อนเข้าไปในหมัดที่ยังค้างอยู่ · ตระกูลเดียวกับบั๊กธง `reflecting`/`countering` ของ P2c-1
   ต้องมีกฎกัน re-entrancy ตั้งแต่ออกแบบ **และต้องแก้ลูป `killChain` ให้เช็ค `att.hp > 0` ก่อนตีซ้ำ**
   (ข้อ 6 ด้านล่าง — วันนี้ยังไม่ถึงเพราะ 👹 ไม่มี cleave แต่กฎใหม่นี้ทำให้ถึงทันที: ตัวตีตายจากหนามกลางหมัดแล้วยังตีต่อ)

   ⚠️ **เงื่อนไขผ่านของเฟสนั้นจะต่างจากทุกเฟสที่ผ่านมา** — การแก้นี้เปลี่ยนเกือบทุกไฟต์
   `battle-differential` จะขึ้นเกือบ 100% ใช้เป็นด่านไม่ได้อีก · ต้องพิสูจน์ด้วยวิธีอื่น
   (เช่น นับว่าการตายทุกใบมี event และมีผู้ฆ่าครบ) · และ **baseline ของ sim ที่วัดไว้ใน P2c-1 ใช้ไม่ได้ ต้องวัดใหม่**

2. **`st.atkStacks` ใช้ร่วมกัน 3 แหล่ง แต่เพดานคนละเลข** — `onRound` max 4 · `onAnyDeath` max 3 · `onKill` max 3
   วันที่เพ็ทตัวเดียวถือสองแหล่ง เพดานต่ำจะบล็อกอีกแหล่งเงียบๆ โดยไม่มี event บอก · วันนี้ยังไม่มีตัวไหนชน

3. **`grit` ไม่อยู่ใน `CLUTCH_EFFECTS`** ⇒ การกันตายชั้นที่ 2-3 ของแมวได้ `skillQuiet` 0ms
   ขัดกับกฎที่เขียนไว้ตรงนั้นเองว่า "จังหวะเป็น-ตาย ได้โมเมนต์เต็มเสมอ แม้เป็นครั้งซ้ำ" (พี่มันคือ `cheatDeath` อยู่ในเซ็ต)
   **เป็นคำถามดีไซน์ที่ยังไม่มีใครตอบ ไม่ใช่บั๊ก**

   กิน `cheatDeath` + `grit` หมดได้ในบีตเดียว · ไม่ใช่บั๊ก (เลขเป็นของ P4) แต่สองงานย่อยนิยามหน่วยคนละอย่าง
   **ต้องรู้ก่อน P3 เพิ่มเพ็ท multi-hit ตัวถัดไป**

   รับ `kind` จาก pass แยก · ของเดิมก่อน P2c-1 ไม่ได้ถูกแตะ

   หนาม · ก้อนสะท้อน · และหมัดสวน 150% ของฟีนิกซ์ (ใหม่ในเฟสนี้) ฆ่าผู้ตีกลางหมัดได้
   วันนี้ยังไม่ถึงเพราะมีแต่ 👹 ที่ถือ `killChain` และมันไม่มี cleave/multiStrike

   ⇒ ป้าย `elementTrinity` โกหกได้ · `liveBuffs` ไม่โชว์ชั้นของ `atkOnHit` · **สถานะ `grit` ของแมวไม่มี badge**
   (P2c-1 เลือกลบป้าย `grit` ทิ้งแทนการต่อสายครึ่งๆ กลางๆ — ต่อจริงต้องทำที่ `liveBuffs()` ไม่ใช่ `buffSources()`)

8. **ช่องว่างของเทสที่รู้ตัว** — ไม่มีเทสคุมเพดาน `stackAtk` ของอูโรโบรอส (max 4) ·

   · สาขา reflect ของธง `countering` พิสูจน์กับไฟต์จริงไม่ได้จนกว่าจะมีเพ็ทที่ถือ `armorStack`

**บทเรียนของเฟสนี้ที่ควรถือต่อ:** เทสบีตที่ป้อน log เขียนมือล้วนคือเหตุที่บั๊กบีตปิดเกมหลุดทุกด่านมาได้
