# ระบบ Passive v1 — ครบทั้ง 27 ตัว

วันที่: 2026-08-27 · ต่อยอดจาก `docs/economy-battle-master-plan.md §5.5` (ตาราง passive + hook design เดิม)
คิว P3 ของ [[rxtu10-pet-overhaul]] — "payoff จริงที่ยังขาด" ของการยกเครื่องเพ็ท

## ปัญหา

ความหายากไม่มีผลตอนสู้นอกจากตัวเลข stat — legendary กับ common ต่างกันแค่ atk/hp คูณกัน
ไม่มีเหตุผลให้ "จัดทีม" นอกจากเอาตัวเลขสูงสุดมาเรียง · pet build depth ถูกถอดออกตอนเลิกระบบศักยภาพ (P2) แล้วยังไม่มีอะไรมาแทน

## กฎเหล็กของทั้งระบบ (user ตัดสิน 27 ส.ค.)

> **passive ไม่เพิ่มจำนวน "จังหวะหมัด" (beat) — เพิ่มได้แค่ FX กับตัวเลข**

มาจากคำสั่งตรงว่า cerberus ควร *"พุ่งทีเดียว แล้วมีอีโมจิเขี้ยว กัด 3 ตัว"* ไม่ใช่ตี 3 จังหวะ
กฎนี้คือสิ่งที่กัน**ไฟต์ยาวขึ้น** — ระบบจังหวะ 4 ชั้นคิดเวลาต่อ event ถ้า passive เพิ่ม event ไฟต์จะยืดทันที
ไฟต์จริง 3v3 วัดได้ **~17 วิ** ก่อนมี passive · **ต้องยังได้ ~17 วิ หลังมี passive**

⇒ cleave/multi-target ทั้งหมด render อยู่ใน beat เดียว · onKill-chain เป็นข้อยกเว้นเดียวที่เพิ่ม beat ได้ (จึงต้องมีเพดาน)

## สิ่งที่จะไม่ทำ (non-goals)

- ไม่จูนตัวเลขให้เป๊ะรอบนี้ (user สั่ง "เดี๋ยวค่อยมาจูนตัวเลขอีกที") — ตัวเลขทั้งหมดเป็น placeholder ที่เหตุผลชัด
- ไม่แตะ `teamPower`/สูตรเหรียญ PvP (ดู "หนี้ที่รู้ตัว")
- ไม่ทำ sim จูนบาลานซ์อัตโนมัติ (v2 — รอบนี้ตรวจด้วย win-rate ดิบพอ)

## A. Data shape

ต่อยอดจาก `passiveOf(def)` ที่มีอยู่แล้ว (คืน `def?.passive || null`)

```js
pet.passive = {
  name: 'ลมหายใจราชัน',   // ชื่อบนป้ายตอน proc
  icon: '🔥',              // อีโมจิบนป้าย + FX
  hook: 'onStart',         // onStart | onRound | onAttack | onHit | onKill | onDeath | aura
  effect: 'aoeOpener',     // primitive id
  value: { pct: 12 },      // ตัวเลข — จูนทีหลัง
}
```
**เพิ่ม passive ใหม่ = เพิ่ม data ไม่แก้ engine** (ตราบใดที่ effect อยู่ในชุด primitive แล้ว)

## B. Hook + primitive (6 hook · 23 primitive)

| hook | ยิงเมื่อ | primitive |
|---|---|---|
| `aura` | ก่อนไฟต์เริ่ม (แก้ stat) | `teamHp` · `teamCrit` · `teamAtk` · `teamAtkPerElement` · `enemyVuln` |
| `onStart` | ไฟต์เริ่ม ก่อนหมัดแรก | `aoeOpener` · `teamHealOpener` |
| `onRound` | ต้นรอบใหม่ทุกรอบ | `regenSelf` · `healLowestAlly` |
| `onAttack` | ก่อนคิดดาเมจ | `cleave` · `targetLowest` · `execute` · `multiStrike` · `atkWhenFull` |
| `onHit` | ก่อนหักเลือดผู้ถูกตี | `damageReduction` · `guardian` · `thorns` · `dodge` |
| `onKill` | หลังศัตรูตาย | `stackAtk` · `killChain` |
| `onDeath` | ตอนตัวเองจะตาย | `revive` · `saveAlly` · `cheatDeath` |

รวม **23 primitive** — ส่วนใหญ่ 3-6 บรรทัด · หลายตัวใช้ร่วมกันต่างแค่ค่า (dodge/damageReduction/regenSelf)

**ลำดับที่ต้องคงไว้เป๊ะ** (เปลี่ยนลำดับ = ผลไฟต์เปลี่ยนทั้งเกม):
`aura` → `onStart` → [ต้นรอบ: `onRound`] → `onAttack` → `onHit` → (ตาย?) `onDeath` → (ตายจริง?) `onKill`

`onDeath` ต้องมาก่อน `onKill` เสมอ — ไม่งั้น phoenix ฟื้นแล้ว trex ยังได้แต้ม kill

## D. Log event + การเล่นใน replay

engine ใส่ event ลง log ตอน passive ทำงาน:
```js
{ t: 'passive', uid, name, icon, effect, targets: ['B0','B1'], amount: 12 }
```

`battleBeats` ปล่อย event ที่ไม่ใช่ `attack` ผ่านไปแบบ `timing: ZERO` อยู่แล้ว (มีคอมเมนต์รอ passive ไว้ตั้งแต่แรก)
⇒ **event passive จึงไม่กินเวลา ไม่ยืดไฟต์** ตรงตามกฎเหล็ก

`BattleReplay` มี dispatch table ตาม `event.t` อยู่แล้ว (คอมเมนต์ว่า "เพิ่ม handler ใหม่ที่นี่ (passive/heal/…)")
เพิ่ม handler `passive` → ยิง 2 อย่าง:
1. **ป้ายชื่อเหนือหัว** ~0.6 วิ (ตาม master plan: เหนือหัว pet ไม่ใช่กลางจอ · หลายอันเรียงคิว)
2. **FX ประจำตัว** ตามตาราง C

## E. FX ที่ต้องเพิ่ม (2 primitive)

| ชื่อ | หน้าที่ | ทำไมพอ |
|---|---|---|
| `banner(uid, name, icon)` | ป้ายชื่อ passive เหนือหัวการ์ด | ใช้ร่วมทุกตัว |
| `sweep(uids, char, stagger)` | ยิงอีโมจิลงหลายการ์ดไล่กัน | ครอบ aoeOpener · cleave · เขี้ยว 3 ใบ · คลื่นทีม · ละออง |

FX ที่เหลือใช้ของเดิมได้หมด (`ring` · `burst` · `pop` · `callout` · `koPuff`)
⚠️ ทั้งคู่ต้องเป็น **pooled ephemeral + transform/opacity เท่านั้น** ตามข้อบังคับ v3 · ห้ามแตะการ์ด

## F. หนี้ที่รู้ตัว (ต้องกลับมาเก็บ)

1. 🔴 **`teamPower` (`atk × maxHp`) จะเริ่มโกหก** — phoenix ที่ฟื้นได้ 1 ครั้งแกร่งกว่าค่าสถิติดิบมาก แต่สูตรเหรียญ PvP กับการจับคู่ยังคิดราคาเท่าเดิม ⇒ คนถือ legendary จะกลายเป็น "เป้าเหรียญถูก" โดยไม่ตั้งใจ · **ยังไม่แก้รอบนี้** เพราะต้องรู้ผลบาลานซ์จริงก่อนว่าแต่ละ passive มีค่าเท่าไหร่
2. 🟠 **`PVP_CONSOLE_MULT = 0.25`** ใส่ไว้ชดเชยที่เอนจินแทบไม่มีพลิก (100%/0%) — passive จะทำให้พลิกได้จริง ต้องวัดใหม่แล้วลด/ถอด
3. 🟠 **สมดุลหอคอย 100 ชั้นจะขยับ** — ทีมบอททุกชั้นสร้างจาก rarity/grade ⇒ ชั้นสูงที่ใช้ legendary จะแกร่งขึ้นพร้อมกับผู้เล่น ต้องดูว่าชั้น 70-100 ยังผ่านได้ไหม

## G. เทส

ตรรกะทั้งหมดอยู่ใน pure module ⇒ `node --test` ครอบได้เกือบหมด
- **แต่ละ primitive**: ทำงานถูก + ไม่ทำงานเมื่อไม่ควร (เช่น revive ครั้งเดียวจริงๆ)
- **ลำดับ hook**: `onDeath` มาก่อน `onKill` (phoenix ฟื้น → trex ไม่ได้แต้ม)
- **กฎเหล็ก**: จำนวน beat ที่ไม่ใช่ passive ต้องไม่เพิ่มเมื่อใส่ cleave (เทียบทีมมี/ไม่มี passive ด้วย seed เดียวกัน)
- **ความยาวไฟต์**: ผลรวม timing ของทีม legendary เต็ม ต้องไม่เกินไฟต์ไม่มี passive เกิน 10%
- **deterministic**: seed เดิม + ทีมเดิม = log เดิมเป๊ะ (ทั้งเกมพึ่งข้อนี้)
- **kill chain**: ไม่วนไม่รู้จบ (เพดาน 2 · ไฟต์จบเสมอภายใน maxTurns)

## H. 🪨 เผื่อ "ดันเจี้ยนหินพาสซีฟ" (user วางแผนไว้ 27 ส.ค. — ยังไม่ build)

แผน: ฟาร์มหินจากดันเจี้ยน → เอามาอัพพลัง passive ได้ **3 ขั้น**
รอบนี้ทำ **โครงตัวเลข** ไว้ให้แล้ว ไม่ได้ทำระบบหิน/ดันเจี้ยน

**สิ่งที่มีแล้ว:**
- `PASSIVE_MAX_LEVEL = 3` · แต่ละ passive มี `step` = ค่าที่เพิ่มต่อขั้น
- `passiveValueAt(p, level)` — ค่าจริงของขั้นนั้น · ตรรกะทุกจุดอ่านผ่านตัวนี้ **ห้ามอ่าน `p.value` ตรงๆ**
- `passiveText(p, level)` — คำอธิบายที่เติมตัวเลขของขั้นนั้น
- เอนจินอ่านขั้นจาก `unit.passiveLv` (ยังไม่มีใครเซ็ต ⇒ ขั้น 1 ทุกตัว) — **พร้อมรับระบบหินโดยไม่ต้องแก้ตรรกะ**

**หลักการตั้ง `step` (สำคัญ อย่าเปลี่ยนโดยไม่คิด):**
- ขั้น 3 ≈ **1.5–1.8 เท่า**ของขั้น 1 ไม่ใช่ 3 เท่า
- `step: 0` = อัพขั้นแล้วค่าไม่ขยับ ใช้กับตัวที่โตแล้วพัง:
  - `kirin killChain` — ตัวเดียวที่เพิ่ม beat จริง อัพได้ = ไฟต์ยืดตามขั้น (ชนงบเวลาที่มีเทสคุม)
  - `cat cheatDeath` / `genie saveAlly` — จำนวนครั้งรอดตาย เพิ่มแล้วเกมยืดและน่ารำคาญ
