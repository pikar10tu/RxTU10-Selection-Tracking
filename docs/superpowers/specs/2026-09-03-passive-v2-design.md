## 3. สถาปัตยกรรม — `parts[]` (P1)

### ปัญหาของโครงเดิม
`petPassives.js` เก็บ **`hook` 1 ค่า + `effect` 1 ค่า ต่อเพ็ท 1 ตัว** และ `effect`
ถูกใช้เป็น **กุญแจ** ทั่วระบบ: `STATUS_ICON` · `STATUS_TEXT` · `STAT_EFFECTS` ·
switch ในเอนจิน · การ์ดหน้าเพ็ท · `battleBuffs.js`

รายการใหม่มี **7 ตัวที่ต้องมีหลายผล**: 🐍 🐦‍🔥 🐘 🦣 🦍 🐱 🐢

### รูปใหม่
```js
cerberus: {
  name: 'ตรีเขี้ยวอสูร', icon: '🐕',
  parts: [ { hook: 'onAttack', effect: 'cleave', value: {...}, step: {...} } ],
  desc: '…', short: '…',
}
```
- **`parts` เป็นทางเดียว** — ไม่รองรับ `hook`/`effect` แบบเก่าคู่ขนาน (สองแหล่งความจริง = พังเงียบ)
- ทุกที่ที่เคยอ่าน `p.effect` ต้องเปลี่ยนเป็นวนทุก part · `STAT_EFFECTS` เช็คแบบ "มี part ไหนไหม"
- `passiveValueAt()` คิดขั้นแยกราย part
- **P1 ห้ามเปลี่ยนพฤติกรรมเกมแม้แต่นิดเดียว** — เทส 976 ตัวเดิมต้องผ่านครบโดยไม่แก้ค่าคาดหวัง
  (แก้ได้แค่ที่อ้าง `p.hook`/`p.effect` ตรงๆ)

### 4.1 `infect` — เชื้อลุกลาม (ตัวยากที่สุด)
- **แปะ:** ไวรัสตีใคร เป้านั้น +1 ชั้น · **เพดาน 5 ชั้น** · ขึ้นจากหมัดไวรัสเท่านั้น
- **ระเบิด:** เป้าที่ติดเชื้อ ถูกตีโดย**ใครก็ได้ในทีมไวรัส** (รวมไวรัสเอง) → ดาเมจเพิ่ม
  = x% ของ atk ไวรัส **× จำนวนชั้น** · เชื้อ**ไม่หาย**ตอนระเบิด
- **ทะลุทุกอย่าง:** ดาเมจเชื้อ **ไม่ผ่าน** `dodge` / `damageReduction` / `teamDamageReduction` /
  `guardian` / `armorStack` — "โรคไม่สนเกราะ" คือเหตุผลที่มันมีอยู่ ถ้าหักลดตามปกติ
  มันจะเหลือแค่ "ดาเมจเพิ่มนิดหน่อย"
- **ส่งต่อ:** ตัวติดเชื้อล้ม → โยนชั้นทั้งหมดไปให้ศัตรูตัวอื่น **สุ่ม 1 ตัว** (ยึดเพดาน 5)
- ⚠️ ไวรัสตายแล้วเชื้อที่แปะไว้**ยังทำงานต่อ** (ตั้งใจ — เพื่อนตีก็ระเบิด)
- ⚠️ สถานะนี้ต้องโผล่บนการ์ดเป็น**ตัวเลขชั้น** ไม่ใช่ป้ายเฉยๆ ไม่งั้นไม่มีใครเข้าใจว่าเกิดอะไร

### 4.2 `taunt` — ตีอกท้าชน
- ต้นรอบ: **ศัตรูทุกตัวที่ออกหมัดในรอบนั้นต้องตีมาที่กอริลลา**
- ระหว่างถูกตีจากผลบังคับ กอริลลา **ลดดาเมจที่รับ x%** (ไม่ใช่ตลอดเวลา — เฉพาะหมัดที่ถูกดึงมา)
- 🔴 **ลำดับความสำคัญของการเลือกเป้า** (ต้องเขียนเป็นเทส):
  `taunt` > `targetLowest` (🦅 กริฟฟิน) > สุ่มปกติ
- 🔴 `guardian` (🐘 รับแทน) ทำงาน**หลัง**เลือกเป้าแล้ว และ **ไม่รับแทนตัวเอง** ⇒ ถ้าเป้าคือกอริลลา บากุไม่แทรก
- ทีมเดียวมีกอริลลา 2 ตัว: **ตัวที่อยู่ช่องซ้ายสุดชนะ** (ต้อง deterministic ไม่งั้น replay ไม่ตรง)

### 4.3 `armorStack` — เกราะปฐพี (🦣 เปลี่ยนกลไก)
- เริ่มไฟต์ได้เกราะ **2 สแตค**
- เกราะกิน 1 สแตค = **กันหมัดนั้นทั้งหมด** (ไม่ใช่โล่ที่มีค่าเลือด) แล้ว **สะท้อน 80% ของดาเมจนั้น
  ใส่ศัตรูทั้งหมด**
- หมดสแตคแล้วรับดาเมจปกติ · ไม่มีการเติมระหว่างไฟต์
- ดาเมจสะท้อน **หักลดตามปกติ** (โดน dodge/DR/เกราะฝั่งตรงข้ามได้) — มีแค่ `infect` ที่ทะลุทุกอย่าง

### 4.4 ขยายของเดิม 8 จุด
| เพ็ท | เดิม | ใหม่ |
|---|---|---|
| 🐱 แมว | `cheatDeath` รอด 1 ครั้ง | รอดแล้ว **ทนต่อได้อีก 2 หมัด** และระหว่างนั้น **atk +50%** |
| 🐦‍🔥 ฟีนิกซ์ | `revive` | คืนชีพ + **ตีผู้สังหาร 150% ของ atk** (แนบบน beat การตาย) |
| 🐕 เซอร์เบอรัส | `cleave` 3 เป้าไม่ซ้ำ | **สุ่ม 3 เป้า ซ้ำตัวเดิมได้** (ตัวเดียวอาจโดน 2–3 ที) · 40% ต่อครั้ง |
| 🦖 ทีเร็กซ์ | `stackAtk` เมื่อ**ตัวเอง**ฆ่า | **ศัตรูล้มโดยใครก็ได้** → hook ใหม่ `onAnyDeath` |
| 🐺 หมาป่า | `teamAtkPerElement` (+x% ต่อเพื่อนสายจู่โจม 1 ตัว) | ออร่าตรงๆ: **เพื่อนสายจู่โจมทุกตัว atk +x%** |
| 🐍 อูโรโบรอส | `regenSelf` | `regenSelf` **+** `stackAtk` ทุกต้นรอบ (2 parts) |
| 🐘 บากุ | `guardian` | `guardian` **+** `regenSelf` (2 parts) |
| 🐉 บาฮามุท | `aoeOpener` | เลขเป็น 150% ของ atk (ค่าจริงรอ P4) |

`teamAtkPerElement` ไม่มีใครใช้แล้ว → **ลบทิ้ง** (ค่าคงที่ที่ไม่มีใครอ่าน อันตรายกว่าค่าที่ผิด)

## 10. ยกไป P2 — ข้อสังเกตจากรีวิว P1

ทั้งหมดนี้ **ไม่ใช่บั๊กของ P1** (พิสูจน์แล้วว่าพฤติกรรมเกมไม่เปลี่ยน: differential 2,587 ไฟต์
เทียบกับ base ได้ผลเหมือนกันทุกไบต์) แต่เป็นข้อสมมติที่ "จริงตราบใดที่ทุกตัวมี part เดียว"
ซึ่ง **P2 คือรอบที่ทำให้มันไม่จริง** — ต้องเก็บก่อนเพิ่มเพ็ทหลาย part

1. **`partWithEffect` หาแบบ effect-first** — `battlePassives.js:240` (guardian) กับ `:315` (saveAlly)
   ดึง part แรกที่ effect ตรง *ไม่ว่าจะอยู่ hook ไหน* แล้วค่อยเช็ค hook ทีหลัง ⇒ ถ้า P2 ใส่
   `guardian` ไว้บน hook อื่นก่อนตัวจริง มันจะเจอตัวผิดแล้ว `continue` = พิทักษ์เงียบไปเฉยๆ
   สำนวนที่ปลอดภัยกว่า: `partsAt(gp, 'onHit').find(x => x.effect === 'guardian')`
2. **`partAt(p, 'onDeath')` เอา part แรกตัวเดียว** — `battlePassives.js:291` · ถ้า P2 มีตัวที่
   `revive` + `cheatDeath` บน `onDeath` พร้อมกัน จะทำงานแค่อันเดียวเงียบๆ
3. **ตัวดักซ้ำใน `battleBeats.js:160` ใช้คีย์ `` `${e.uid}:${e.effect}` ``** ⇒ เพ็ทที่มีสอง part
   ใช้ effect เดียวกัน part ที่สองจะถูกลดเป็น `skillQuiet` เงียบๆ (บั๊กตระกูลเดียวกับ CLAUDE.md ข้อ 15
   — ปลายทางไกลๆ ที่แอบสมมติรูปฟิลด์ไว้)
4. **เทสหลาย part ยังไม่ล็อกลำดับ** — สเปกบอกว่า "ลำดับใน parts = ลำดับที่ event โผล่บนจอ"
   แต่ `battlePassives.test.js:404-424` เช็คแค่ว่ามีครบ ไม่ได้เช็คลำดับ · เพิ่มบรรทัดเดียวพอ:
   `assert.deepEqual(effects, ['regenSelf', 'healLowestAlly'])`
5. **`upgradable.length >= 20`** (`battlePassives.test.js:322-334`) เปลี่ยนหน่วยไปแล้ว —
   เดิมนับ *ตัวเพ็ท* ตอนนี้นับ *part* · เท่ากันวันนี้ (27 ตัว × 1 part) แต่ P2 จะทำให้เลขพอง
6. **ออปชัน `effect` ของ `effectText`** (`petPassives.js:264-275`) รับไว้แล้วแต่ยังไม่ได้ใช้ —

### กฎ 4 ข้อที่ P2 ต้องทำตาม

1. **หนึ่งเพ็ท × หนึ่ง hook = หนึ่งจังหวะ ไม่ว่าจะมีกี่ part** — ยิง event ตามลำดับใน `parts[]`
   แต่ให้ **ใบสุดท้ายของก้อนเท่านั้นที่ถือเวลาหยุด** ที่เหลือ 0ms
   (กลไกนี้มีอยู่แล้วใน `battleBeats.js` ชื่อ `openQuiet`/`openGroup` ที่ใช้กับยกแรก — ทำซ้ำแบบเดียวกัน
   อย่าเพิ่มชั้นเวลาใหม่) · ถ้าปล่อยตามโค้ดวันนี้ เพ็ท 3 part ที่ effect ไม่ซ้ำกันจะได้
   `SKILL_PAUSE` 200ms × 3 = **หยุด 600ms ติดกันในรอบเดียว**
2. **ตัวดักซ้ำต้องเลิกใช้คีย์ `` `${e.uid}:${e.effect}` ``** (`battleBeats.js:160`) — เพ็ทที่มีสอง part
   ใช้ effect เดียวกัน part ที่สองจะโดนลดเป็น `skillQuiet` เงียบหายไปเลย · ใส่ลำดับ part
   หรือ `tag` ลงในคีย์ด้วย
3. **ลำดับใน `parts[]` = ลำดับที่เห็นบนจอ** — เป็นสัญญาที่เขียนไว้ในสเปกแล้วแต่ยังไม่มีเทสล็อก
   P2 ต้องเพิ่ม `assert.deepEqual(effects, [...])` ในเทสเพ็ทหลาย part (ดู §10 ข้อ 4)
4. **เพดานป้ายต่อการ์ด `STATUS_MAX = 3`** วัดไว้ตอนทุกตัวมี part เดียว: เฉลี่ย 1.09 ใบ ชนเพดานแค่ 4.7%
   P2 ต้อง **วัดใหม่** หลังเพิ่มเพ็ทหลาย part — ถ้าชนเพดานบ่อยขึ้นมาก ผู้เล่นจะมองไม่เห็นว่าตัวเองติดอะไร

## 12. กติกาการเขียนคำอธิบายสกิล (บังคับตั้งแต่ P2 เป็นต้นไป)

user สั่ง 3 ก.ย. 2026: **"อธิบายตรงๆ พร้อมแจ้งตัวเลขเลย · ไม่เอาคำไม่ทางการ"**

1. **แจ้งตัวเลขทุกตัวที่ข้อมูลมี** — ทุกคีย์ใน `value` ที่เป็นตัวเลขต้องถูกพูดถึงใน `desc`
   ผ่านช่อง `{...}` · ค่าที่ไม่ถูกพูดถึง = ผู้เล่นไม่มีทางรู้ว่ามีอยู่
2. **ห้ามพิมพ์ตัวเลขที่จูนได้ลงไปตรงๆ** — พิมพ์ได้เฉพาะเลขที่ตายตัวอยู่ในโค้ด
   (เช่น "เหลือเลือด 1", "ล้มศัตรู 1 ตัว") · ที่เหลือให้ `passiveText()` เติมจาก `value`/`step`
3. **ห้ามใช้คำย่อ/คำไม่ทางการ** — "คริ" ต้องเป็น "คริติคอล" · "เทิร์น" ต้องเป็น "รอบ"
   (ทั้งเกมใช้คำว่า "รอบ" ที่อื่นหมดอยู่แล้ว)
4. **เขียนให้อ่านได้ทางเดียว** — เลี่ยงคำที่แยกวรรคผิดแล้วความหมายเปลี่ยน
   (ของเดิม "ตัวรองรับ 50% ของดาเมจ" อ่านได้ว่า "ตัว-รองรับ" → แก้เป็น "ตัวรองโดน 50%")
5. **`short` กับ `STATUS_TEXT` ของคนละกลไกต้องอ่านไม่เหมือนกัน** — ฟีนิกซ์ (ฟื้นคืนชีพ 35%)
   กับแมว (รอดด้วยเลือด 1) เคยอ่านได้ว่า "กันตายได้ 1 ครั้ง" เหมือนกันเป๊ะทั้งคู่

**เทสบังคับกฎ 1–3 อยู่ใน `src/data/petPassives.test.js` แล้ว** (3 เคส) ⇒ เพ็ทใหม่ของ P2/P3
ที่เขียนคำอธิบายผิดกติกาจะเทสแดงทันที ไม่ต้องมานั่งไล่ตรวจด้วยตา
