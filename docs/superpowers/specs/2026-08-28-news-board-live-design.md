# กระดานข่าวมีชีวิตชีวา

วันที่: 2026-08-28 · สเปก B ของชุดงาน 28 ส.ค. (ต่อจาก A `team-pet-tower-ui` และ C `skill-moment`)

## ปัญหา

`components/home/NewsBoard.vue` อ่าน `news` 10 doc ล่าสุดตอน mount แล้วนิ่งสนิท และมีของป้อนเข้าแค่ 2 ทาง:
แอดมินโพสต์เอง กับ `useAchievements.js` ยิงตอนปลดแอชชีฟเมนต์ — ซึ่ง**คนหนึ่งปลดได้ครั้งเดียวในชีวิต**

ผลคือกระดานข่าวของชั้นปีที่มีคนเล่นอยู่ทุกวัน แสดงข่าวเดิมค้างเป็นสัปดาห์ ทั้งที่จ่ายค่า read ไป 10 ครั้งทุกครั้งที่มีคนเปิดหน้า Home
ในเกมมีเหตุการณ์น่าเล่าเกิดขึ้นตลอดเวลา (ไต่หอคอย เปิดกาชา ทุบสถิติ อัปบ้าน) แต่ไม่มีอันไหนไปโผล่บนกระดานเลย

## ทางออก: กระดานสองเลน

| | เลน `roster` — ข่าวไหลเร็ว | เลน `news` — ข่าวอยู่ยาว |
|---|---|---|
| เก็บที่ | `rows.<uid>.ev` ในแถวตัวเอง | doc ใน collection `news` |
| ต้นทุน | ส่วนใหญ่เกาะไปกับ write ที่เกิดอยู่แล้ว | 1 write/ข่าว |
| เพดาน | 3 รายการ/คน (ข่าวใหม่เบียดข่าวเก่าของตัวเอง) | ไม่มี — จึงต้องหายากจริง |
| อายุ | โชว์ไม่เกิน 7 วัน | อยู่จนแอดมินลบ |
| เกณฑ์ | เหตุการณ์ประจำวัน | **ครั้งแรก / ที่หนึ่งของรุ่น** เท่านั้น |

**หลักที่ใช้ตัดสินว่าข่าวไหนอยู่เลนไหน:** ถ้าอีก 3 เดือนยังอยากให้คนย้อนมาเห็น = เลน `news` · ถ้าอ่านผ่านแล้วจบ = เลน `roster`

## ทำไมถึงถูกลงทั้งที่ข่าวเยอะขึ้น

`roster/current` ถูกอ่านอยู่แล้ว **1 read ต่อเซสชัน** แล้วแคชใน `members` store (จอเพื่อน/หอคอย/สนาม/มินิเกม/Time Attack ใช้ร่วมกันหมด)
และแถวของตัวเองก็ถูกเขียนอยู่แล้วหลังทุกกิจกรรมที่ทำให้สถิติเปลี่ยน (`syncRosterRow`)

⇒ ข่าวจากหอคอย/PvP/มินิเกม/Time Attack/บ้าน/เพ็ท **ไม่เพิ่ม write แม้แต่ครั้งเดียว** — แค่พ่วง `ev` ไปกับ write ที่จะเกิดอยู่แล้ว
เหลือควิซกับฟาร์มที่เป็น write ใหม่จริง (ถี่ต่ำ: อย่างมาก 1 ครั้งต่อรอบควิซ / ต่อการส่งออเดอร์ใหญ่)

ฝั่งอ่าน: Home เรียก `loadRoster()` (1 read และจอถัดไปได้ใช้ฟรี) + `news` ลด `limit(10)` → `limit(5)`

**สุทธิ 10 read → 6 read ต่อการเข้า Home** และเป็น read ที่หน้าอื่นได้ประโยชน์ต่อ

แพทเทิร์นนี้ไม่ใช่ของใหม่ — เป็นอันเดียวกับประวัติ PvP (`utils/pvpHistory.js` + `syncRosterRow({history})`) ที่ deploy ไปแล้ววันก่อน

## รูปข้อมูล

เพิ่มฟิลด์ `ev` ในแถว roster **ต่อท้ายหลัง `h`** (ตำแหน่งต้องคงที่ — ดูกับดักข้อ 2):

```js
ev: [ { k: 'tw', v: 40, t: 1787880000000 },      // ใหม่สุดอยู่หน้า สูงสุด 3
      { k: 'mg', g: 'g2048', v: 2, t: 1787879000000 } ]
```

- `k` = ชนิดข่าว (2 ตัวอักษร) · `v` = ตัวเลขประกอบ · `t` = `Date.now()` · `g` = คีย์ย่อย (เฉพาะ `mg`/`ta`)
- **ไม่เก็บข้อความไทย** — ประกอบประโยคตอนอ่านจากรหัส ⇒ แก้สำนวนทีหลังได้โดยไม่ต้องย้อนแก้ข้อมูล และไม่เปลืองไบต์
- ไม่เก็บชื่อคน — ดึงจาก `rosterRows[uid].n` ตอนอ่าน ⇒ เปลี่ยนชื่อเล่นแล้วข่าวเก่าเปลี่ยนตาม
- ขนาด: 3 รายการ × ~30 ไบต์ × 105 คน ≈ **9.5KB** จากลิมิต 1MB/doc (`h` กินอยู่แล้ว 24KB)
  ⚠️ เพิ่มจำนวนรายการเมื่อไหร่ต้องคำนวณใหม่

`t` ใช้ `Date.now()` ฝั่ง client เพราะ `serverTimestamp()` ใส่ใน array ไม่ได้ — นาฬิกาเครื่องเพี้ยนแล้วลำดับเพี้ยนตาม ยอมรับได้ (ใช้แค่เรียงกับโชว์ "เมื่อกี้")

## การรวมฟีด

`utils/newsFeed.js` — ตรรกะล้วน ไม่แตะ Firestore/Vue (เทส `node --test src/utils/newsFeed.test.js`)

```js
pushEvent(list, ev)                          // ต่อหน้าสุด ตัดเหลือ EVENT_MAX (3) — คู่แฝดของ pushHistory
buildFeed(rows, newsDocs, { now, myUid })    // → [{ id, icon, text, t }] เรียงใหม่→เก่า
```

`buildFeed` ทำ 4 อย่าง:
1. กาง `ev` ของทุกแถว → ประกอบข้อความไทยจาก `k`/`v`/`g` + ชื่อจาก `rows[uid].n`
2. **ตัดข่าวที่เก่ากว่า 7 วันทิ้ง** (เฉพาะเลน `roster`) — ถ้าไม่ตัด คนที่เลิกเล่นไปแล้วจะค้างหัวกระดานถาวร เพราะ `ev` ไม่มีวันหมดอายุเอง
3. รวมกับ doc จากเลน `news` (ไม่ตัดอายุ — เลนนี้ตั้งใจให้อยู่ยาว และทำให้กระดานไม่มีทางว่าง)
4. เรียงตาม `t` → **จำกัด 2 บรรทัดต่อคน** → ตัดเหลือ 10

ข่าวของตัวเองขึ้นด้วย ใช้คำว่า "คุณ" — และแทรกทันทีตอนเกิด ไม่ต้องรอรีโหลด (แถวตัวเองใน `members.rosterRows` ถูกอัปเดตใน `syncRosterRow` อยู่แล้ว)

## หน้าตา

คงโครงเดิมของ `NewsBoard.vue` ไว้ทั้งหมด (แถบพับบนสุดของ Home ~44px) เปลี่ยน 3 อย่าง:

1. **บรรทัดที่ปิดอยู่สลับข่าวเองทุก 3.5 วิ** — fade + slide 200ms
   หยุดเมื่อ: กางกระดาน · แท็บไม่ได้อยู่หน้าจอ (`visibilitychange`) · `prefers-reduced-motion` · มีข่าวเดียว
   ใช้แค่ `opacity`/`transform` — **ห้าม `backdrop-filter`/blur** (บทเรียน iOS Safari จาก `battlefx`)
   ⚠️ เคลียร์ timer ใน `onUnmounted` ทุกทาง
2. **เวลาแบบ "12 นาทีที่แล้ว"** แทนวันที่เต็ม — ข่าวไหลเร็วต้องรู้ว่าสดแค่ไหน
3. **ไอคอนแยกหมวด** ผ่าน `<Emoji>` เดิม: 🏰 หอคอย · ⚔️ สนาม · 📚 ควิซ · 🎮 มินิเกม · 🌾 ฟาร์ม · 🏠 บ้าน · ✨ กาชา · 🐾 เพ็ท · 📢 แอดมิน

ไม่มีข่าว = ซ่อนทั้งแถบเหมือนเดิม · ฟอนต์ทุกจุด ≥ `.7rem` · ไม่ต้อง `Teleport` (ไม่ใช่ overlay)
สำนวนตาม `docs/voice-guide.md` เรียบๆ ไม่หวือหวา:

> 🏰 มายด์ ไต่หอคอยถึงชั้น 40 · 📚 บีม ตอบควิซถูกรวด 10 ข้อ · 🎮 คุณ ทำคะแนน 2048 ขึ้นอันดับ 2 ของรุ่น

## firestore.rules

`news` เปิด `type` เพิ่มจาก `'achievement'` เป็น allowlist 4 ค่า ส่วนที่เหลือคุมเหมือนเดิมทุกข้อ:

```
allow create: if (request.auth != null
      && request.resource.data.type in ['achievement','legendary','tower100','record1']
      && request.resource.data.msg is string && request.resource.data.msg.size() <= 140
      && request.resource.data.keys().hasOnly(['msg','icon','type','uid','ts'])
      && request.resource.data.get('uid', '') == request.auth.uid)
  || isAdmin();
```

⚠️ **ต้อง `firebase deploy --only firestore:rules`** — push ขึ้น Pages ไม่แตะ rules (กับดักข้อ 3 ใน CLAUDE.md)
แถว `roster` ไม่ต้องแก้ rules เลย — `affectedKeys().hasOnly([uid])` ครอบ `ev` ให้อยู่แล้ว

## กับดัก

1. **`buildRosterRow(u, prev)` ต้องพ่วง `ev` เดิม** เหมือนที่พ่วง `h` — ไม่งั้นข่าวหายทุกครั้งที่ sync (เปลี่ยนชื่อ/อัปบ้าน/จบมินิเกมก็ sync) บั๊กนี้เคยเกิดจริงกับ `h` มาแล้ว
2. **`ev` ต้องต่อท้ายหลัง `h` เสมอ** — `rosterRowChanged` เทียบด้วย `JSON.stringify` ซึ่งอาศัยลำดับคีย์คงที่ สลับตำแหน่งเมื่อไหร่ = ยิงเขียนเปล่าทุกรอบ
3. **`roster/current` รับไหว ~1 write/วินาที** — เพิ่ม write จากควิซ/ฟาร์มเข้าไป ตอนทั้งรุ่นเล่นพร้อมกันอาจชน คงพฤติกรรมเดิมคือ **ล้มเหลวแล้วเงียบ** (`console.warn` ไม่ toast ไม่ retry) ข่าวหายอันเดียวไม่กระทบการเล่น
4. **rules ไม่ตรวจเนื้อในแถว roster** ⇒ เปิด DevTools ปลอมข่าวตัวเองได้ **ยอมรับ** เพราะปลอมได้แค่แถวตัวเอง และ**ไม่มีรางวัลใดผูกกับข่าว** (บทเรียนจาก PvP: ห้ามผูกรางวัลกับข้อมูลที่อีกฝ่ายจดเอง)
5. **ห้ามมี `v-html` ใน NewsBoard** — เลน `news` เปิดรับ type ใหม่แปลว่าข้อความมาจากผู้เล่น ต้องผ่าน `cleanText` ตอนเขียน และใช้ `{{ }}` อย่างเดียวตอนอ่าน (CLAUDE.md ข้อ 8)
6. **CLAUDE.md ข้อ 9** — จุดยิงข่าวหลายจุดอยู่หลัง `patchUser` ซึ่งเปลี่ยน `userData` แบบ synchronous ⇒ **หยิบค่า (ชั้น/เลเวล/เกรด/อันดับ) เก็บเป็นตัวแปรก่อนเรียก `patchUser` เสมอ** (`TimeAttackView.vue:293` ทำถูกอยู่แล้ว ใช้เป็นแบบ)
7. **ชั้น 100 ยิง `tower100` ทางเดียว** ไม่ยิง `tw` ซ้ำ (100 ลงท้าย 0)
8. `ev` ที่ `k` ไม่รู้จัก (มาจากเวอร์ชันใหม่กว่า) = **ข้ามเงียบ** ห้าม throw — คนที่ยังไม่รีโหลดหน้าเว็บจะอ่านแถวของคนที่อัปเดตแล้ว
