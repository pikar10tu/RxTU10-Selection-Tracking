# ดันคนเข้าสนามประลอง: เควสประจำวัน + ทางเดินตอนแพ้

วันที่ 31 ส.ค. 2026 · สถานะ: อนุมัติดีไซน์แล้ว รอเขียนแผน

## โจทย์

อยากให้คนเข้าสนามประลอง (PvP) เยอะขึ้น

จากการสังเกตของ user คนที่ไม่เล่นติดอยู่ 2 อย่างพร้อมกัน:

1. **ไม่รู้ว่ามี / ไม่เคยกดเข้าไป** — สนามอยู่ในเมนูลึก ไม่มีอะไรชวน
2. **เข้าไปแล้วยังไม่มีทีม เลยถอย** — สอดคล้องกับข้อมูลตอนทำ matchmaking ที่พบว่ามีแค่ 13 จาก 52 คนที่จัดทีมเพ็ทไว้

ข้อ 1 คือปัญหา discovery — เควสประจำวันแก้ได้ตรงๆ
ข้อ 2 คือกำแพงที่ **รอบนี้จงใจไม่แตะ** (ดูหัวข้อ "ไม่ทำรอบนี้")

## ของที่มีอยู่ตอนนี้

- `src/utils/dailyQuest.js` — `QUEST_GOALS = { quiz: 5, farm: 3, gacha: 2 }` เป็นค่าคงที่ตายตัว
  รางวัลเมื่อครบ: รายได้ idle ×1.5 24 ชม. + ตั๋วอัญเชิญฟรี ×3
- `src/components/home/DailyQuestCard.vue` — การ์ดบนหน้าแรก 3 แถว เป็นข้อความล้วน **กดไม่ได้**
- ตัวนับถูก bump จาก 4 ที่: `useFarm.js:93` (farm) · `QuizView.vue:530` + `TimeAttackView.vue:343` (quiz) · `ShopView.vue:213` (gacha)
- `useArena.fight()` — บุกได้วันละ 5 ครั้ง (`PVP_DAILY_ATTACKS`) · เขียนผลด้วย `patchUser` ครั้งเดียวใน `applyResult()`
- `BattleReplay.vue:102` — modal สรุปรับ `winText` / `loseText` จากผู้เรียกได้อยู่แล้ว
- `useAppConfig.js:20` — `pvpOpen` ดีฟอลต์ **false** แอดมิน toggle ได้สดจาก Firestore

## สิ่งที่จะทำ

### 1. เปลี่ยนช่องที่ 3 ของเควสจาก "อัญเชิญเพ็ท" เป็น "ลองสู้ในสนามประลอง"

ข้อความบนการ์ด: **`⚔️ ลองสู้ในสนามประลอง  0/1`**

เกณฑ์จริงคือสู้ 1 ครั้งโดยแพ้ก็นับ แต่ **ห้ามเขียนคำว่า "แพ้ก็นับ" ลงบนจอ** —
พูดถึงการแพ้ตั้งแต่ยังไม่ได้เริ่มเป็นการปลูกความคาดหวังว่าจะแพ้ คำว่า "ลอง" สื่อว่าไม่ต้องกดดันอยู่แล้ว
คนที่แพ้แล้วเห็นตัวนับขึ้นเป็น 1/1 จะเข้าใจกติกาเองทันที

เจตนาคือ "ให้คนเข้ามา" ไม่ใช่ "ให้เก่ง" คนอ่อนที่แพ้รวดต้องจบเควสได้ ไม่งั้นกลายเป็นบทลงโทษรายวัน
และการแพ้จะถูกส่งต่อไปยังข้อ 3 (จอแพ้ชี้ทางไปอัพเพ็ท) แทนที่จะเป็นทางตัน

**รางวัลไม่เปลี่ยนเลย** — ยังได้ตั๋วอัญเชิญฟรี ×3 เหมือนเดิม
ที่เอาออกคือ *การบังคับ* ไม่ใช่ตัวกาชา คนยังเปิดกาชาอยู่ดีเพราะมีตั๋วอยู่ในมือ แต่เปิดตอนที่อยากเปิด

### 2. เป้าเควสต้องขึ้นกับ `pvpOpen` (กันเควสทำไม่ได้ทั้งชั้นปี)

`pvpOpen` เป็น flag ที่แอดมินปิดได้สดๆ ถ้าเป้าเป็น PvP ตายตัวแล้วสนามถูกปิด
= ทุกคนทำเควสไม่ครบ ไม่ได้บัฟ ×1.5 จนกว่าจะมีคนสังเกตเห็น

⇒ `QUEST_GOALS` ค่าคงที่ ต้องกลายเป็นฟังก์ชัน `questGoals(pvpOpen)`

- `pvpOpen = true` → `{ quiz: 5, farm: 3, pvp: 1 }`
- `pvpOpen = false` → `{ quiz: 5, farm: 3, gacha: 2 }` (พฤติกรรมเดิมเป๊ะ)

ทุกที่ที่ตัดสินความครบ (`questComplete` → `questClaimable` และการ์ดบนหน้าแรก)
ต้องอ่านเป้าจากฟังก์ชันเดียวกันนี้ — ห้ามมีที่ไหนถือรายการเป้าเป็นของตัวเอง
(`questNotClaimed` ดูแค่ flag `claimed` ไม่ต้องรู้เป้า — ไม่ต้องแก้)

**ตัวนับ `gacha` ยังคงอยู่และยัง bump จาก `ShopView` ต่อไป** ถึงจะไม่ได้ใช้ตอน `pvpOpen` เปิด
เพราะแอดมินสลับ flag กลางวันได้ ตัวนับที่ยังเดินอยู่แปลว่าสลับแล้วเควสไม่รีเซ็ตความคืบหน้าของใคร

### 3. นับ PvP ตอนไฟต์จบ — เกาะไปกับ write เดิม

bump ที่ `useArena.applyResult()` ซึ่งเขียน `patchUser` อยู่แล้ว **⇒ 0 write เพิ่ม**
นับทั้งชนะและแพ้ · นับเฉพาะไฟต์ที่เขียนผลสำเร็จ (`ok === true`) ไม่งั้นเน็ตหลุดแล้วเควสเดินหน้าลอยๆ

⚠️ CLAUDE.md ข้อ 9 — หยิบ `auth.userData?.dailyQuest` มาคำนวณ **ก่อน** เรียก `patchUser`
(แพทเทิร์นเดียวกับ `nextNonce` ที่บรรทัดบนในฟังก์ชันเดียวกัน)

### 4. แถวเควสกดได้ = ตัวแก้ "ไม่รู้ว่ามี"

นี่คือส่วนที่แก้ปัญหาข้อ 1 จริงๆ สำคัญกว่าตัวเควสเอง

ตอนนี้แถวเป็นข้อความล้วน คนอ่านว่า "สู้ในสนามประลอง 0/1" แล้ว **ไม่รู้ว่าสนามอยู่ตรงไหน**
ทำให้ทั้ง 3 แถวกดแล้วเด้งไปหน้าที่เกี่ยวข้อง:

| แถว | ไปที่ |
|---|---|
| 📝 ทำข้อสอบ | `/quiz` |
| 🌱 ปลูกพืช | `/play/farm` |
| ⚔️ ลองสู้ในสนามประลอง | `/arena` |
| 🎰 อัญเชิญเพ็ท (เมื่อ `pvpOpen` ปิด) | `/shop` |

แถวที่ทำครบแล้วยังกดได้ (ไม่ล็อก) — ทำเสร็จแล้วอาจอยากกลับไปเล่นต่อ
เป็น `<button>` ไม่ใช่ `<div @click>` เพื่อให้กด Enter/Tab ได้ตามมาตรฐาน a11y ของแอป

### 5. จอแพ้ชี้ทางต่อ (หอคอย + PvP)

เพิ่มช่อง `loseTip` ให้ modal สรุปของ `BattleReplay` — ข้อความสั้น 1 บรรทัด + ปุ่มเดียว
โผล่เฉพาะตอนแพ้ ต่อท้าย `loseText` เดิม

ปุ่มเลือกตามสถานะจริงของคนนั้น (คนที่เหรียญไม่พอไม่ควรถูกส่งไปหน้าที่กดอะไรไม่ได้):

- มีตั๋วอัญเชิญฟรี **หรือ** เหรียญพอเปิดกาชา → **🎰 อัญเชิญเพ็ท** → `/shop`
- ไม่พอ → **🐾 อัพเกรดเพ็ท** → `/pets`

ข้อความต่างกันตามโหมด:
- หอคอย: "ทีมยังสู้ชั้นนี้ไม่ไหว — ลองเสริมทีมก่อนไต่ต่อ"
- สนามประลอง: "อยากชนะบ้าง? ลองเสริมทีมก่อนบุกรอบหน้า"

**ตรรกะเลือกปุ่มอยู่ฝั่ง view** (ที่มองเห็นเหรียญ/ตั๋ว) — `BattleReplay` แค่รับ `{ text, label, to }` มาวาด
ไม่ต้องรู้เรื่องราคากาชาหรือ auth store เลย (คงความเป็น component วาดอย่างเดียวไว้)

กดปุ่มแล้ว = ปิด overlay ไฟต์ก่อนแล้วค่อย navigate ไม่งั้น overlay ค้างทับหน้าใหม่

## ไม่ทำรอบนี้

- **ไม่แตะกำแพงจัดทีม** — คนที่ยังไม่มีทีมจะถูกพาไปหน้าจัดทีมเหมือนเดิม (user เลือกเอง)
- ไม่แตะโควตาบุก 5 ครั้ง/วัน · ไม่แตะสูตรเรต/เหรียญ · ไม่แตะรางวัลเควส

## ความเสี่ยงที่รู้แล้ว

**คนที่ยังไม่มีทีมจะทำเควสวันนั้นไม่ครบ = ไม่ได้บัฟ ×1.5 ทั้งวัน** อาจมีเสียงบ่นช่วงแรก
ตัดสินใจรับความเสี่ยงนี้ไว้ก่อน — ถ้าเกิดขึ้นจริงค่อยเติมปุ่ม "จัดทีมให้เลย" ในหน้าสนามทีหลัง
เป็นการเพิ่มล้วนๆ ไม่ต้องรื้อของที่ทำรอบนี้

## เกณฑ์ว่าสำเร็จ

- เควสประจำวันแสดง "ลองสู้ในสนามประลอง 0/1" เมื่อ `pvpOpen` เปิด และกลับเป็น "อัญเชิญเพ็ท 0/2" เมื่อปิด
- สู้ PvP 1 ครั้งแล้วแพ้ → ตัวนับขึ้นเป็น 1/1 และกดรับรางวัลได้ (ถ้าอีก 2 ช่องครบ)
- ไม่มีคำว่า "แพ้ก็นับ" หรือคำที่พูดถึงการแพ้โผล่บนการ์ดเควส
- ไฟต์ที่เขียนผลไม่สำเร็จ → ตัวนับไม่ขยับ
- กดแถวเควสแล้วไปหน้าที่ถูกต้องทุกแถว
- แพ้ในหอคอยและใน PvP → เห็นข้อความ + ปุ่มเดียวที่ชี้ไปหน้าที่กดต่อได้จริงตามเหรียญ/ตั๋วที่มี
- ชนะ → ไม่มีข้อความชี้ทางโผล่มา
