# สเปก: ออเดอร์ฟาร์ม — บอร์ด 5 ช่องเติมเองตามเวลา

วันที่ 22 ส.ค. 2026 · brainstorm กับ user เสร็จแล้ว (อนุมัติดีไซน์ + เลือกเลย์เอาต์ B จาก mockup)

## ที่มา

โปรเจกต์ย่อยที่ 2 จาก 3 ที่แตกออกมาตอน user สั่ง "อยากอัพเกรดระบบเกม" (22 ส.ค.):

1. ฟาร์มมีชีวิต — ✅ deploy แล้ว (`33c44b8`)
2. **ออเดอร์ฟาร์ม** ← สเปกนี้
3. อาหารเพ็ท — ยังไม่ brainstorm

**ปัญหาที่แก้:** ผลผลิตจากฟาร์มมีปลายทางเดียวคือกดขาย → ไม่มีเหตุผลให้ปลูกหลากหลาย
คนเล่นจะหาพืชที่คุ้มสุดต่อชั่วโมงแล้วปลูกแต่ตัวนั้นวนไป · ออเดอร์ทำให้พืชที่ "ไม่คุ้มสุด" มีที่ใช้
และทำให้มีเหตุผลกลับเข้าแอพระหว่างวัน

**ทำไมไม่ใช่บอร์ดรีเซ็ตรายวัน:** ตอน brainstorm เสนอแบบรายวันไปก่อน user ค้านว่า "ไม่อยากให้มันรีเซตไปเปล่าๆ"
และขอแบบ Hay Day — ปฏิเสธใบที่ไม่ถูกใจได้แต่ต้องรอ · แบบช่อง-เติม-เอง แก้ตรงจุดกว่า เพราะออเดอร์ที่ยัง
ไม่ได้ส่งไม่หายไปตอนเที่ยงคืน และคนที่เข้ามาเล่นเป็นช่วงๆ ไม่โดนลงโทษ

## ขอบเขต

**ทำ**

1. บอร์ด 5 ช่องในหน้าฟาร์ม · แต่ละช่องมีออเดอร์ 1 ใบ (ขอพืช 1–3 ชนิด)
2. กด "ส่ง" เมื่อผลผลิตพอ → หักผลผลิต + ได้เหรียญ → ช่องนับถอยหลัง **30 นาที** แล้วเติมใบใหม่
3. กด "ไม่เอาใบนี้" → ช่องนับถอยหลัง **2 ชั่วโมง** แล้วเติมใบใหม่
4. ออเดอร์สุ่มจากพืชที่ปลดล็อกแล้วเท่านั้น จำนวนชิ้นผูกกับเวลาโตของพืช

**ไม่ทำ — จงใจ**

- ไม่มีการรีเซ็ตรายวัน · ออเดอร์ที่ยังไม่ส่งค้างอยู่ได้ไม่จำกัดเวลา
- ไม่ผูกกับระบบเควสรายวัน (`utils/dailyQuest.js`) — คนละระบบ ไม่ยุ่งกัน
- ไม่มีการเร่งเวลารอด้วยเหรียญ/ตั๋ว
- ไม่มีออเดอร์พิเศษ/ออเดอร์ตามเทศกาล
- ไม่แตะ `useFarm.js`, `firestore.rules`

**บันทึกภายใน (ไม่ต้องสื่อสารกับนักศึกษา):** user สั่งว่ารอบนี้ **รางวัลเป็นเหรียญอย่างเดียวไปก่อน**
แต่ให้เผื่อไว้ว่าอนาคตจะมีระบบอื่นเข้ามาแล้วอาจปรับรางวัลตรงนี้ → **โครงรางวัลต้องเป็น object
(`{ coins: n }`) ไม่ใช่ตัวเลขโดดๆ** จะได้เติม `tickets` หรือไอเทมทีหลังโดยไม่ต้องแก้ทั้งเส้นทาง

## ดีไซน์

### 1. เก็บข้อมูล — `farm.orders` ใน user doc

array ยาว 5 (index = ช่อง) ตามแพทเทิร์นเดียวกับ `farm.plots` ที่มีอยู่แล้ว
(Firestore แก้ array ทีละ index ไม่ได้ → เขียนทั้ง array เหมือนที่ `useFarm.commit()` ทำอยู่)

ช่องมี 2 สภาพ แยกกันด้วยการมีคีย์ `items`:

```js
// มีออเดอร์รออยู่
{ id: 'o1787376242813x7f3', items: { tomato: 3, corn: 2 }, reward: { coins: 10880 } }

// ช่องว่าง กำลังนับถอยหลัง
{ at: 1787378042813 }        // ms epoch ที่จะเติมใบใหม่
```

**ตัดสินใจ: เก็บเนื้อออเดอร์ไว้จริง ไม่สร้างสดจาก seed**
ทางเลือกที่ประหยัดกว่าคือเก็บแค่ seed แล้วคำนวณเนื้อออเดอร์สดตอนแสดงผล (ไม่ต้องเขียนตอนเติมช่อง)
แต่เนื้อออเดอร์ขึ้นกับรายชื่อพืชที่ปลดล็อก **ณ ตอนคำนวณ** → พออัปเลเวลบ้าน ออเดอร์ที่กำลังปลูกค้าง
จะเปลี่ยนเนื้อไปเงียบๆ และถ้าแก้ข้อมูลใน `data/crops.js` ทีหลัง (ซึ่งเพิ่งทำไปในโปรเจกต์ก่อนหน้า)
ออเดอร์เก่าก็เพี้ยนตาม · เก็บไว้ตรงๆ = เห็นอะไรได้อันนั้น ราคาที่จ่ายคือเขียนเพิ่มตอนช่องเติมใบใหม่

**`reward` ถูกแช่ไว้ตอนสร้างใบ** ด้วยเหตุผลเดียวกัน — ปรับ `sellPrice` ทีหลังแล้วออเดอร์ที่ค้างอยู่ไม่เปลี่ยนค่ากลางคัน

**`id`** ใช้กันกดส่งซ้ำจากการกดรัว (UI เทียบ id ที่กำลังส่งอยู่) — ไม่ได้กันฝั่งเซิร์ฟเวอร์ ซึ่งรับได้เพราะแอพนี้ trust-based ทั้งใบ

### 2. ตรรกะบริสุทธิ์ — `data/farmOrders.js`

ค่าคงที่ทั้งหมดอยู่บนหัวไฟล์ จูนได้โดยไม่ต้องแตะตรรกะ:

| ค่า | ตั้งต้น | ความหมาย |
|---|---|---|
| `ORDER_SLOTS` | 5 | จำนวนช่อง |
| `REFILL_MS` | 30 นาที | รอหลังส่งสำเร็จ |
| `REROLL_MS` | 2 ชม. | รอหลังปฏิเสธ (แพงกว่า เพื่อไม่ให้รีโรลรัวจนได้ใบที่คุ้มสุดเสมอ) |
| `REWARD_MULT` | 1.5 | คูณราคาขายรวม |
| `VARIETY_BONUS` | 0.10 | บวกต่อชนิดที่เกินชนิดแรก (2 ชนิด = ×1.6 · 3 ชนิด = ×1.7) |
| `MAX_KINDS` | 3 | ชนิดพืชสูงสุดต่อใบ |
| `KIND_WEIGHTS` | `[45, 35, 20]` | น้ำหนักสุ่มจำนวนชนิด 1/2/3 |

**จำนวนชิ้นผูกกับเวลาโต** (ไม่ใช่สุ่มลอยๆ) — กันออเดอร์อย่าง "ต้นไม้เงินตรา ×5" ที่กินเวลา 15 วัน:

| เวลาโตของพืช | ขอกี่ชิ้น |
|---|---|
| ≤ 15 นาที | 3–8 |
| ≤ 180 นาที | 2–5 |
| ≤ 1440 นาที | 1–3 |
| มากกว่านั้น | 1–2 |

**ฟังก์ชันที่ export:**

```js
buildOrder(seed, crops, now)   // → { id, items, reward } · pure ยกเว้นรับ now/seed เข้ามา
orderReward(items)             // → { coins } · คิดจาก sellPrice × qty × ตัวคูณ
canDeliver(order, inventory)   // → boolean
missingItems(order, inventory) // → { cropId: ขาดกี่ชิ้น } · ใช้ระบายสีชิปที่ขาด
normalizeOrders(raw, now)      // → array ยาว ORDER_SLOTS เสมอ (คนเก่า/ข้อมูลเพี้ยน → ช่องพร้อมใช้)
dueSlots(orders, now)          // → [index] ของช่องที่ถึงเวลาเติมแล้ว
```

**สุ่มแบบมี seed** (`mulberry32` ~5 บรรทัด) เพื่อให้เทสได้จริง — `buildOrder(42, …)` ต้องได้ผลเดิมทุกครั้ง
seed จริงตอนใช้งานมาจาก `Date.now()` + index ช่อง

**พฤติกรรมที่ต้องเป็นจริง (= เคสเทส)**

- `buildOrder` ด้วย seed เดิม + รายการพืชเดิม → ผลลัพธ์เหมือนเดิมทุกฟิลด์
- ออเดอร์ขอเฉพาะพืชที่ส่งเข้าไปเท่านั้น (ไม่มีพืชที่ยังไม่ปลดล็อกหลุดเข้ามา)
- จำนวนชิ้นอยู่ในช่วงของ bracket ตามเวลาโตของพืชนั้นเสมอ (ไล่ทุกพืชทั้ง 16 ชนิด × หลาย seed)
- จำนวนชนิดอยู่ระหว่าง 1..3 และไม่มีพืชซ้ำชนิดในใบเดียว
- **จำนวนชนิดถูก clamp ด้วยจำนวนพืชที่ปลดล็อกจริง** (`kinds = min(สุ่มได้, พืชที่ปลดล็อก)`) → ปลดล็อกแค่ 1 ชนิดก็ยังสร้างออเดอร์ได้ ไม่ loop ค้าง ไม่ throw
- ส่ง `crops` เป็น array ว่างเข้าไป → คืน `null` (ไม่ throw) และ `refillDue` ต้องข้ามช่องนั้นไปเฉยๆ
- `orderReward` ตรงสูตร: 1 ชนิด = ×1.5 · 2 ชนิด = ×1.6 · 3 ชนิด = ×1.7 (ปัดเป็นจำนวนเต็ม)
- `canDeliver` → true เมื่อของครบพอดี · false เมื่อขาดแม้ชิ้นเดียว · false เมื่อ inventory ว่าง
- `missingItems` คืนเฉพาะชนิดที่ขาด พร้อมจำนวนที่ขาดจริง
- `normalizeOrders`: `undefined` / `[]` / array สั้นไป / ยาวเกิน / สมาชิกเป็น `null` → ได้ array ยาว 5 เสมอ
- `dueSlots` คืนเฉพาะช่องที่ `at <= now` · ช่องที่มีออเดอร์อยู่แล้วไม่ถูกนับ

### 3. ต่อกับ user doc — `composables/useFarmOrders.js`

- `orders` — computed จาก `auth.userData.farm.orders` ผ่าน `normalizeOrders`
- **`refillDue()`** — ถ้ามีช่องที่ถึงเวลา สร้างใบใหม่ให้ทุกช่องที่ถึงเวลา **ในการเขียนครั้งเดียว**
  เรียกตอน `onMounted` ของบอร์ด และตอนตัวจับเวลาเดินถึงศูนย์ · ถ้าไม่มีช่องถึงเวลา **ต้องไม่เขียนอะไรเลย**
  (กันเขียนทุกครั้งที่เปิดหน้า)
- **`deliver(i)`** — เช็ก `canDeliver` ซ้ำก่อนเขียนเสมอ → หัก inventory + `coins: increment(reward.coins)`
  + ตั้งช่องเป็น `{ at: now + REFILL_MS }` **ในการเขียนครั้งเดียวผ่าน `patchUser`**
  (ถ้าแยกเขียนแล้วเน็ตหลุดกลางคัน จะกลายเป็นหักของแต่ไม่ได้เงิน)
- **`reroll(i)`** — ตั้งช่องเป็น `{ at: now + REROLL_MS }` · ยืนยันก่อนด้วย `useConfirm` เพราะกดพลาดแล้วรอ 2 ชม.

ทุกการเขียนใช้ `auth.patchUser(optimistic, server)` ตามแพทเทิร์นของโปรเจกต์ · caller เป็นคน toast เอง

### 4. UI — `components/farm/FarmOrders.vue` (เลย์เอาต์ B ที่ user เลือก)

- **รางเลื่อนแนวนอน** — การ์ดกว้างคงที่ ~172px, `overflow-x: auto` + `scroll-snap-type: x mandatory`
  · **`overflow-x` ต้องอยู่ที่รางเท่านั้น ห้ามให้หน้าเลื่อนแนวนอนทั้งหน้า**
- จุดบอกตำแหน่ง 5 จุดใต้ราง
- การ์ดที่มีออเดอร์: ชิปพืช (อีโมจิ + `×จำนวน`) · รางวัล · ปุ่ม "ส่ง" กับปุ่ม "✕"
  · ชิปของชนิดที่ **ขาด** ขึ้นสีแดง · ปุ่มส่งเป็น disabled พร้อมข้อความ "ของไม่พอ"
- การ์ดที่กำลังรอ: ⏳ + เวลาที่เหลือ นับถอยหลังทุกวินาที
- **a11y:** `<Emoji>` เป็น `<img alt="" aria-hidden>` → ชิปที่มีแต่อีโมจิจะไม่มีเสียงอ่าน
  ต้องใส่ชื่อพืชเป็นข้อความซ่อน (`.sr-only`) หรือ `aria-label` บนชิป เช่น "มะเขือเทศ 3 ชิ้น"
- **ตอนกดส่ง แสดงชื่อพืชเต็มในกล่องยืนยัน** — การ์ดแคบเลยเหลือแต่อีโมจิ ชื่อเต็มจึงต้องโผล่ตอนที่สำคัญที่สุด
- ฟอนต์ทุกจุด ≥ `.7rem` · เอฟเฟกต์ (ถ้าใส่) ต้องเคารพ `prefers-reduced-motion`

**ตำแหน่งในหน้า:** `FarmView.vue` เรียงเป็น แปลงปลูก → **บอร์ดออเดอร์** → ร้านค้าฟาร์ม
(ออเดอร์กินผลผลิตจากกล่องซึ่งอยู่ท้าย `FarmGrid` เลยควรอยู่ติดกัน)

### 5. Schema + คนเก่า

เพิ่ม `orders: []` เข้า `USER_DEFAULTS.farm` ใน `data/userSchema.js`
· คนเก่าที่ยังไม่มีฟิลด์นี้ → `normalizeOrders` ให้บอร์ดพร้อมใช้ครบ 5 ช่องทันทีตั้งแต่เปิดหน้าแรก
· **ไม่ต้องมี migration หรือปุ่มให้แอดมินกด**

**rules ไม่ต้องแก้:** เจ้าของเขียน `farm.*` ได้อยู่แล้ว และรางวัลสูงสุดที่เป็นไปได้ (ต้นไม้เงินตรา ×2 ≈ 210,000)
ยังห่างจากเพดาน 50 ล้านมาก

## ความเสี่ยงและสิ่งที่รับไว้

| เรื่อง | ท่าที |
|---|---|
| เขียน Firestore เพิ่มตอนช่องเติมใบใหม่ | รวบเขียนทีเดียวทุกช่องที่ถึงเวลา · ไม่มีช่องถึงเวลา = ไม่เขียนเลย · สูงสุดไม่กี่ครั้ง/วัน |
| ปรับนาฬิกาเครื่องเพื่อข้ามเวลารอ | **รับไว้** — แอพนี้ trust-based และเวลาโตของพืชก็ใช้นาฬิกาเครื่องอยู่แล้ว การไปแก้จะต้องมี backend |
| เปิดสองแท็บแล้วส่งพร้อมกัน | last-write-wins เหมือนการขายผลผลิตเดิม · `canDeliver` เช็กซ้ำก่อนเขียนกันกรณีปกติได้ |
| ออเดอร์เป็นท่อเงินเข้าเพิ่มให้ฟาร์ม | ตั้งใจตาม user (×1.5 + โบนัส) · ตัวเลขทุกตัวอยู่บนหัวไฟล์เดียว ปรับลงได้ทันทีถ้าเฟ้อ · จดไว้ใน ROADMAP ว่านี่คือ faucet ใหม่ |
| เลเวลบ้านต่ำ ปลดพืชน้อย ออเดอร์ซ้ำๆ | ยอมรับได้ — Lv.1 ปลดแล้ว 2 ชนิด และอัปบ้านขั้นแรกไม่แพง |
