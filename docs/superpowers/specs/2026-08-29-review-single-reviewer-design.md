# ลดเกณฑ์ peer-review เหลือ 1 คน/ข้อ + ถอนแบนเนอร์ "ยังไม่ผ่านการตรวจ"

**วันที่:** 29 ส.ค. 2026
**ที่มา:** user สั่ง — ข้อที่ปล่อยให้เพื่อนทำจากนี้ผ่านมือทีมวิชาการแล้ว จึงไม่ต้องเตือนว่ายังไม่ตรวจ
และลดเกณฑ์จาก 2 คน/ข้อ เหลือ 1 คน/ข้อ เพื่อให้คลังเดินหน้าเร็วขึ้น

## เกณฑ์ใหม่

`computeStatus()` เป็นแหล่งความจริงเดียวของสถานะตรวจ ตัดสินจากตัวนับ `reviewPass` / `reviewFail` บน doc

| เสียง (pass-fail) | เดิม | ใหม่ |
|---|---|---|
| 0-0 | `pending` รอตรวจ | `pending` รอตรวจ |
| 1-0 | `half` ค้าง 1 เสียง | **`passed` ผ่านตรวจ** |
| 0-1 | `half` ค้าง 1 เสียง | **`failed` ไม่ผ่าน** |
| 1-1 (ของเก่า) | `conflict` ขัดแย้ง | `conflict` ขัดแย้ง — คงเดิม |
| 2-0 / 0-2 (ของเก่า) | `passed` / `failed` | เหมือนเดิม |
| 2-1 / 1-2 (เสียงที่ 3) | เสียงข้างมากตัดสิน | เหมือนเดิม |

**สถานะ `half` ถูกลบทิ้งทั้งระบบ** — ไม่มีทางเกิดขึ้นใหม่ได้อีก
ผลพลอยได้: ข้อที่เพื่อนตรวจไปแล้ว 1 เสียงและค้างอยู่ **ได้ข้อสรุปทันทีย้อนหลัง** ไม่เสียของ

`needsReviewBy()` — "ข้อนี้ต้องให้ฉันตรวจไหม":
- กันตรวจข้อตัวเอง (ยกเว้น `source === 'import'` เพราะ `createdBy` คือคนกด import ไม่ใช่คนแต่ง)
- กันตรวจซ้ำ (`reviewedBy` มี uid เราแล้ว)
- ข้าม `retired`
- **เกณฑ์จำนวน: `reviewedBy.length < 1`** (เดิม `< 2`) — ยกเว้น `conflict` ที่ยังรอคนที่ 3

## เอาน้ำหนักสุ่มคิวออก

เดิมคิวสุ่มถ่วงน้ำหนัก `conflict ×8 · half ×4 · pending ×1` เพื่อเร่งข้อค้างครึ่งทางให้ครบ 2 เสียง
พอเหลือ 1 คน/ข้อ **"ข้อค้างครึ่งทาง" ไม่มีอยู่จริงแล้ว** เหตุผลของน้ำหนักจึงหมดไป

- ลบ `REVIEW_WEIGHTS`, `reviewWeight()`, `pickWeighted()` ออกจาก `utils/questionReview.js`
- `ReviewView.pickNext()` สุ่มแบบเท่ากันหมด (uniform) จากคิว
- ข้อ `conflict` ยังถูกหยิบเจอบ่อยกว่าสัดส่วนจริงในคลังอยู่ดี เพราะ `load()` ดึงก้อน conflict มา **ครบทุกข้อ**
  แต่ดึงก้อน `pending` มาแค่หน้าต่างสุ่ม 40 ข้อ — ความถี่มาจากโครงการโหลด ไม่ต้องพึ่งน้ำหนัก

## จุดที่ต้องแก้

| ไฟล์ | แก้อะไร |
|---|---|
| `utils/questionReview.js` | `computeStatus` ตัดสินที่ 1 เสียง · `needsReviewBy` `< 1` · ลบ `half` จาก `REVIEW_STATUS_LABEL` · ลบ `REVIEW_WEIGHTS`/`reviewWeight`/`pickWeighted` · แก้คอมเมนต์หัวไฟล์ |
| `views/ReviewView.vue` | เลิก import `pickWeighted` → สุ่ม uniform · query คิวเหลือ `where('reviewStatus','==','conflict')` · แถบความคืบหน้าเอา "ค้าง 1 เสียง" ออก (แต่ยังบวก `half` ที่ค้างใน meta รวมเข้า "รอตรวจ") · เปลี่ยนชื่อ `HALF_LIMIT` → `CONFLICT_LIMIT` |
| `views/QuizView.vue` | ลบกล่อง `.qv-notice` + CSS class |
| `views/QuestionsView.vue` | ลบ `<option value="half">` จากฟิลเตอร์สถานะตรวจ + CSS `.qz-badge.rv.half` |
| `views/AdminView.vue` | ลบ key `half` จากตัวนับ progress ตอน "คำนวณ meta ใหม่" + แก้คอมเมนต์ที่อ้าง `pending → half` |
| `utils/questionReview.test.js` | แก้เคสที่อ้างเกณฑ์ 2 คน + ลบเทส weight/pickWeighted + เพิ่มเคส 1 เสียงตัดสิน |
| `ROADMAP.md` | อัปเดตรายการที่อ้างแบนเนอร์ + เกณฑ์ 2 คน |

**ไม่ต้องแก้ `firestore.rules`** — rules คุมแค่รูปทรงการเขียน (ผลรวมเสียง +1 พอดี, `reviewedBy` ต้องมี uid ตัวเอง,
มี subdoc `reviews/{uid}` จริง) ไม่ได้ฮาร์ดโค้ดค่าสถานะ ยกเว้น `'pending'` ใน `isReviewReset()` ซึ่งยังถูกอยู่

**ไม่มีจุดไหน auto-ถอนเผยแพร่เมื่อผลเป็น `failed`** — การเผยแพร่ยังเป็นการกดของวิชาการเสมอ
เกณฑ์ที่ลดลงจึงไม่ทำให้ข้อหลุดจากหน้าทำข้อสอบเองโดยไม่มีคนสั่ง

## ข้อมูลเก่าที่ค้างอยู่ (migration)

`reviewStatus` เป็นฟิลด์ที่ **เก็บไว้บน doc** (จำเป็น เพราะ `load()` query จากมันตรงๆ) ไม่ใช่ค่าคำนวณสด
ข้อที่ตอนนี้เก็บค่า `'half'` ไว้จะยัง stale จนกว่าจะเขียนทับ

- **ปุ่ม "🔄 ซิงก์ระบบตรวจ" ใน Admin เก็บกวาดให้เอง** — มันเทียบ `q.reviewStatus !== computeStatus(q)`
  แล้วเขียนค่าใหม่ พอ `computeStatus` เปลี่ยนนิยาม ข้อ `half` ทั้งหมดจะถูกเขียนเป็น `passed`/`failed` ให้
- **ไม่กดก็ไม่พัง:** ป้ายสถานะในหน้าคลังใช้ `reviewStatusKey()` ซึ่งคำนวณสด → ถูกทันที ·
  ข้อ `half` เก่าหลุดจากคิวตรวจทันทีเพราะ query ไม่ถามหา `'half'` แล้ว (และ `needsReviewBy` ก็บอกว่าไม่ต้องตรวจ)
  ที่ยังเพี้ยนคือ **ตัวเลขในแถบความคืบหน้า** ซึ่งอ่านจาก `reviewMeta/main.progress` — จึงคงการบวก `half`
  รวมเข้าช่อง "รอตรวจ" ไว้กันตัวเลขรวมหายไปดื้อๆ พอกดซิงก์แล้ว `half` จะเป็น 0 เองและบรรทัดนี้กลายเป็น no-op

**สิ่งที่ user ต้องทำหลัง deploy:** กด "🔄 ซิงก์ระบบตรวจ" ใน Admin หนึ่งครั้ง

## นอกขอบเขตรอบนี้

**รวมกลุ่มโรค 70 กลุ่มให้ตรงเกณฑ์สภาเภสัชกรรม** — user ถามมาในรอบเดียวกัน แต่แยกเป็นรอบถัดไป
เครื่องมือมีครบแล้ว (`utils/topicMerge.js` + กล่อง "🏷️ จัดการหมวด / กลุ่มโรค" ใน `QuestionsView`)
ที่ขาดคือของนอกโค้ด: รายการกลุ่มโรคตามเกณฑ์สภาฯ ฉบับจริง, รายชื่อ 70 กลุ่มปัจจุบันจาก Firestore,
และการจับคู่ซึ่งเป็นดุลพินิจวิชาการ · ถ้าต้องรวมหลายสิบคู่ควรทำโหมด "ใส่ตารางแมพแล้วรันรวด" เพิ่ม
