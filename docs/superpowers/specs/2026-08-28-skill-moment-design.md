พี่น้อง: [สเปก A — UI จัดทีม/เพ็ท/หอคอย](2026-08-28-team-pet-tower-ui-design.md)
ต่อยอดจาก: [สเปก passive v1](2026-08-27-passive-v1-design.md) · [สเปก จังหวะ replay](2026-08-23-battle-replay-pacing-design.md)

## ปัญหา

ทุกวันนี้ passive beat มี `timing = ZERO` ทุกตัว (`battleBeats.js`) — ป้ายชื่อเด้งขึ้น**พร้อมกับ**ที่ไฟต์เดินต่อ
ผู้เล่นไม่มีจังหวะได้อ่านเลยว่าสกิลชื่ออะไร ทำอะไร ระบบ passive ที่เพิ่งลงไป (27 ส.ค.) จึงแทบมองไม่เห็น

ผู้ใช้ต้องการจังหวะแบบ 7DS Grand Cross: **แบนเนอร์สกิลขึ้น → ได้อ่าน → ผลค่อยลง**

---

## ข้อมูลจริงที่บังคับรูปทรงของดีไซน์

จำลอง 300 ไฟต์ 3v3 (สุ่มสปีชีส์/เกรด 0–5) นับจาก log ของ `simulateBattle()` โดยตรง

```
หมัดหลัก/ไฟต์   avg 27.1   p90 36
passive/ไฟต์    avg 19.6   p90 36   max 74
เวลาไฟต์ตอนนี้  avg 16.1s  p90 20.9s  max 25.4s
```

แยกตาม effect (ครั้ง/ไฟต์):

```
regenSelf 5.10 · healLowestAlly 4.35 · damageReduction 2.98 · cleave 1.47
guardian 0.84 · thorns 0.80 · duoRegen 0.60 · targetLowest 0.40
… ที่เหลือ < 0.3 ทุกตัว (revive 0.12 · saveAlly 0.16 · killChain 0.17 · aoeOpener 0.24)
```

**51% ของ passive คือฮีลซ้ำ ๆ** ตัวละ 2–5% ของเลือดสูงสุด ทุกต้นรอบ
👉 ถ้าใส่ดีเลย์ทุกอันตัวละ 700ms = **+13.7s เฉลี่ย · p90 +25s** ไฟต์กลายเป็น 30–46 วิ

> 🔑 บทเรียนที่ห้ามลืม (จาก `battleBeats.js` ฉบับแรก): เดาสัดส่วนแล้วคำนวณงบเวลา = ผิดคนละเรื่อง
> เคยเดา heavy 15% แต่ของจริง 53% → ไฟต์ยาว 33 วิ **ต้องนับจาก log จริงเสมอ แล้วคุมด้วยโควตา**

## ดีไซน์ — 3 ชั้น + ยกแรกรวมกลุ่ม

### ชั้นของ passive beat

| ชั้น | ได้เมื่อไหร่ | เวลา | เกิด/ไฟต์ (วัดแล้ว) |
|---|---|---|---|
| ✨ **สปอตไลต์** | โควตา **3** ต่อไฟต์ + จังหวะเป็น-ตาย | **1200ms** | 3.0 |
| · **ป้ายผ่าน** | ครั้งแรกของสกิลนั้นในไฟต์ (ที่ไม่ได้สปอตไลต์) | **250ms** | 0.8 |
| **เงียบ** | ครั้งที่ 2+ ของสกิลเดิม | **0ms** (เท่าวันนี้เป๊ะ) | 14.2 |

**ชั้นเงียบยังมีป้าย + FX ครบเหมือนเดิมทุกครั้ง — แค่ไม่หยุดเวลา**
นี่คือตัวที่ทำให้ระบบไม่ระเบิด: ฮีลซ้ำ 14.2 ครั้ง/ไฟต์ ตกลงชั้นนี้หมด

### ยกแรก (ก่อนหมัดแรก) — ขึ้นพร้อมกันทั้งหมด

`applyAuras()` + `runOnStart()` รันก่อนหมัดแรกเสมอ (`battleEngine.js:32–34`)
วัดได้ **1.8 ตัว/ไฟต์ · p90 3 · max 7** — ถ้าไล่ทีละตัวจะกิน 7 × 1.2 = 8.4s ในไฟต์แย่สุด

👉 **ป้ายทุกใบเด้งขึ้นพร้อมกัน ค้างรวม 1100ms ครั้งเดียว ไม่ว่าจะกี่ตัว**
ครอบ 🐋 พรมหาสมุทร · ✨ ละอองเวทมนตร์ · 🦭 ยอดนักซัพพอร์ต · 🐺 สัญชาตญาณฝูง · 🦉 นัยน์ตาหยั่งรู้ (aura)
และ passive `onStart` ที่ไม่ใช่การโจมตี

**ยกเว้น `aoeOpener` (🔥 ลมหายใจราชัน ของบาฮามุท)** — รอกลุ่มหายก่อน แล้วเล่นเป็น **สปอตไลต์เต็ม**
เพราะมันเป็น "การกระทำ" (สาดไฟใส่ทุกตัว) ไม่ใช่บัฟที่ติดอยู่เฉย ๆ · นับนอกโควตา 3 (เกิดแค่ 0.24/ไฟต์)

### คะแนนแจกสปอตไลต์

pure function ใน `battleBeats.js` แพทเทิร์นเดียวกับ `scoreOf()` ของหมัด:

```
score = (จังหวะเป็น-ตาย ? 1.0 : 0)          // revive · cheatDeath · saveAlly
      + (ครั้งแรกของสกิลนั้นในไฟต์ ? 0.5 : 0)
      + min(0.5, ผลจริง / เลือดสูงสุดของเป้า)  // regen 4% ตกรอบเองโดยธรรมชาติ
```

กฎเพิ่ม:
- **1 สกิลได้สปอตไลต์ได้ครั้งเดียวต่อไฟต์** (กันแมวน้ำตัวเดียวกินโควตาหมด) — คีย์ = `uid + ':' + effect`
- ครั้งซ้ำที่ไม่ใช่จังหวะเป็น-ตาย (`score < 1.0`) ไม่มีสิทธิ์สปอตไลต์เลย
- เรียงคะแนนมากไปน้อย หยิบจนครบโควตา

### งบเวลาที่ได้จริง (โมเดลเดียวกัน รัน 300 ไฟต์)

```
เดิม   avg 16.1s   p90 20.9s   max 25.4s
ใหม่   avg 20.8s   p90 25.9s   max 30.6s      (+4.7s เฉลี่ย)
```

ยาวขึ้น ~29% — เป็นราคาที่ผู้ใช้รับทราบและอนุมัติแล้ว
เพดานคงที่เพราะเป็นโควตา ไม่ใช่เกณฑ์ตายตัว (ทีมที่ passive แน่นกว่าก็ไม่ทำให้ยาวขึ้นอีก)

ปุ่มปรับถ้าอยากสั้นลงทีหลัง: โควตา 3→2 ได้ **19.6s / p90 24.8s** (ประหยัดแค่ 1.2s
เพราะยกแรกกับหมัดปกติเป็นตัวหลัก ไม่ใช่โควตา — อย่าไปเสียเวลาจูนผิดตัว)

## ไทม์ไลน์สปอตไลต์ (1200ms)

```
   0ms  หรี่ฉาก opacity 0 → .55 (180ms) + การ์ดเจ้าของเรืองแสง/ยกขึ้น
 180ms  แบนเนอร์เลื่อนเข้า (240ms)
        ┌────────────────────────────┐
        │ 🔥  ลมหายใจราชัน            │
        │ สาดเปลวไฟใส่ศัตรูทุกตัว 12%  │
        └────────────────────────────┘
 420ms  ค้างอ่าน 550ms
 970ms  แบนเนอร์ออก + ฉากคืน (230ms) — พร้อมกับ **ผลลง**:
        FX เดิมทั้งชุด (sweep/pop/callout) + หลอดเลือดขยับ
1200ms  จบ ไฟต์เดินต่อ
```

**ผลต้องลงหลังแบนเนอร์ ไม่ใช่พร้อมกัน** — นี่คือหัวใจของสิ่งที่ผู้ใช้ขอ
⚠️ วันนี้ `applyPassive()` อัปเดต `hp.value` ทันทีต้นฟังก์ชัน (บรรทัด ~383) — ชั้นสปอตไลต์ต้อง**เลื่อนไปเฟสผล**
ไม่งั้นหลอดเลือดจะขยับตั้งแต่แบนเนอร์ยังไม่ทันขึ้น = ผู้เล่นเห็นผลก่อนเห็นเหตุ

ข้อบังคับการเรนเดอร์:
- 🚫 **ห้ามใช้ `backdrop-filter` / `filter: blur()`** — เป็นตัวฆ่าเฟรมบน iOS Safari
  ฉากหรี่ = `<div>` สีทึบ + `opacity` + `will-change: opacity` เท่านั้น
- แบนเนอร์เคลื่อนด้วย `transform`/`opacity` เท่านั้น (ห้าม layout property)
- เคารพ `prefers-reduced-motion`: ตัดการเลื่อน เหลือ fade — **แต่ยังต้องหยุดครบ 1200ms**
  (จุดประสงค์คือให้อ่าน ไม่ใช่ให้ดูอนิเมชัน)
- ป้ายผ่าน 250ms = FX เดิมทั้งหมด แค่ `await wait(250)` ต่อท้าย ไม่มีของใหม่

## จุดแก้ในโค้ด

### 1. `utils/battleBeats.js` — แจกชั้นให้ passive (pure, เทสได้)

เพิ่มค่าคงที่ + pass ใหม่:

```js
export const PASSIVE_TIMING = {
  spotlight: { windup: 420, motion: 0, hitstop: 550, tail: 230 },  // รวม 1200
  glance:    { windup: 0,   motion: 0, hitstop: 250, tail: 0   },  // รวม 250
  mute:      { windup: 0,   motion: 0, hitstop: 0,   tail: 0   },
}
export const OPEN_GROUP_MS = 1100
export const PASSIVE_SPOT_QUOTA = 3
export const CLUTCH_EFFECTS = new Set(['revive', 'cheatDeath', 'saveAlly'])
```

beat ของ passive ได้ฟิลด์ใหม่ `pTier: 'spotlight' | 'glance' | 'mute' | 'openGroup'`

**ยกแรกทำยังไงให้ยังคง "1 event = 1 beat"** (ข้อบังคับเดิมของ `buildBeats` — index ต้องตรงกับ log):
event ในกลุ่มยกแรกได้ `pTier: 'openGroup'` timing 0 **ทุกตัว ยกเว้นตัวสุดท้ายของกลุ่ม**
ที่ได้ `hitstop: OPEN_GROUP_MS` → replay ยิงป้ายรัวจนครบ (0ms ห่างกัน = ตาเห็นเป็นพร้อมกัน) แล้วค้างทีเดียว

`aoeOpener` ที่อยู่ในหน้าต่างยกแรก **ไม่นับเข้ากลุ่ม** → ได้ `spotlight` (นอกโควตา)

### 2. `components/battle/BattleReplay.vue`

- `applyPassive()` เป็น `async` แล้วแยกเป็น 3 เส้นทางตาม `beat.pTier`
  - `mute` / `openGroup` (ไม่ใช่ตัวท้าย) → เหมือนวันนี้เป๊ะ ยิง FX แล้วคืนทันที
  - `openGroup` ตัวท้าย → ยิง FX แล้ว `await wait(OPEN_GROUP_MS)`
  - `glance` → ยิง FX แล้ว `await wait(250)`
  - `spotlight` → เข้าไทม์ไลน์ 1200ms ข้างบน (**ผลลงตอน 970ms**)
- ทุก `await` ต้องใช้ `wait()` ตัวที่ผูก `gen` อยู่แล้ว + เช็ค `if (g !== gen) return` หลังทุกครั้ง
  (มิฉะนั้น reset ระหว่างสปอตไลต์ = ฉากหรี่ค้างถาวร)
- `step()` มี re-entrancy guard (`stepGen`) อยู่แล้ว — ไม่ต้องแตะ

### 3. กดค้างเร่ง (FF)

`FF_SCALE` เพิ่มชั้น passive: `spotlight: 1` · `openGroup: 1` · `glance: 0.3` · `mute: 0`
**ห้ามให้ FF ย่อสปอตไลต์** — ไม่งั้นกลายเป็นปุ่มข้ามสกิล (เหตุผลเดียวกับที่ `heavy`/`finish` ห้ามแตะ)

### 4. แตะเพ็ทแล้วหยุดอ่าน — แก้ 3 จุด

ฟีเจอร์นี้ **มีอยู่แล้ว** (`inspect()` บรรทัด 566 = `paused = true` + เปิดป๊อปอัป) แต่พังอยู่

| # | อาการ | แก้ |
|---|---|---|
| 4a | 🐞 **ปิดหน้าต่างแล้วไฟต์ค้าง** — `@click="inspectUid = null"` (บรรทัด 116, 125) ไม่เคยคืน `paused` เลย ต้องไปกด ▶️ เอง | ทำ `closeInspect()` = `inspectUid = null` + `paused = false` + `step()` · ผูก `Escape` ด้วย |
| 4b | ป๊อปอัปโชว์แค่ **ชื่อ** สกิล (บรรทัด 124) ไม่บอกว่าทำอะไร | เติมคำอธิบายจาก `passiveText(insp.passive)` ใต้ชื่อ |
| 4c | ไม่มีทางรู้ว่าตัวไหนมีสกิล ถ้าไม่ไล่แตะทีละใบ | จุดไอคอนสกิลเล็ก ๆ มุมการ์ดในสนาม (static ไม่ใช่ FX — วาดครั้งเดียวตอนเริ่มไฟต์) |

⚠️ 4a ต้องไม่ปลด pause ถ้าผู้เล่น**กดปุ่ม ⏸️ พัก เอง**ก่อนจะแตะดูเพ็ท —
เก็บ `pausedBeforeInspect` ตอนเปิด แล้วคืนค่านั้นตอนปิด

⚠️ 4c ห้ามทำเป็น element ที่ re-render ทุกเฟรม — สถาปัตยกรรม v3 บังคับว่าการ์ดต้อง static
(เคสกระตุก iOS Safari ที่แก้ไป 4 รอบกว่าจะเจอว่าเป็น paint-bound จาก raster การ์ดเต็มใบ)

## เทส

`node --test src/utils/battleBeats.test.js` — เคสใหม่:
- ฮีลตัวเดิมซ้ำ 5 ครั้ง → ครั้งแรกได้ `glance`/`spotlight` · ครั้งที่ 2–5 ได้ `mute` ทั้งหมด
- โควตาเต็มที่ 3 เสมอไม่ว่า passive จะมีกี่ตัว (ยัด 40 ตัวก็ยัง 3)
- `revive` / `cheatDeath` / `saveAlly` ได้สปอตไลต์แม้เป็นครั้งซ้ำ
- สกิลเดียวกัน (`uid:effect` เดียวกัน) ได้สปอตไลต์ไม่เกิน 1 ครั้ง
- ยกแรก: ทุก event ได้ `openGroup`, มีตัวเดียวที่ `hitstop === OPEN_GROUP_MS` และเป็นตัวสุดท้ายของกลุ่ม
- `aoeOpener` ในยกแรกได้ `spotlight` ไม่ใช่ `openGroup`
- ไฟต์ที่ไม่มี passive เลย → `beats` เท่าเดิมทุกประการ (ไม่มี regression กับไฟต์เก่า)
- `beats.length === log.length` เสมอ (ข้อบังคับเดิม)

สคริปต์วัดงบเวลา — เก็บเข้ารีโปเป็น `scripts/passive-pacing-sim.mjs`
เพื่อให้รอบหน้าที่จะจูนเลข **วัดก่อนเดา** ได้ทันที (นี่คือกับดักที่เคยทำพลาดมาแล้ว)

## เกณฑ์ว่าเสร็จ

1. `npm run build` ผ่าน
2. `node --test src/utils/battleBeats.test.js` ผ่านทั้งเก่าและใหม่
3. `node scripts/passive-pacing-sim.mjs` รายงาน avg ≤ 21s และ p90 ≤ 26s
4. ดูไฟต์จริงในเบราว์เซอร์: แบนเนอร์ขึ้นก่อน → เลข/หลอดเลือดขยับตาม (ไม่ใช่พร้อมกัน)
5. ฮีลรอบ 2+ ของตัวเดิม ไฟต์ไม่สะดุด
6. แตะการ์ด → หยุด · ปิด → เดินต่อทันที · กด ⏸️ เองแล้วแตะการ์ดแล้วปิด → **ยังพักอยู่**
7. เทสบนมือถือจริง (iOS Safari) — ไม่มีเฟรมตกตอนสปอตไลต์
