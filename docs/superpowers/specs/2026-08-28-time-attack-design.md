# Time Attack — โหมดข้อสอบจับเวลา

วันที่: 2026-08-28

## ปัญหา

`StudyView.vue:24` มีการ์ด "⏱️ Time Attack — แข่งกับเวลา 4 / 15 นาที" ติดป้าย "เร็วๆ นี้" มาตั้งแต่ SP1 (23 มิ.ย.)
โหมดที่มีอยู่ (ทั่วไป / Zen / ข้อที่เคยผิด) ล้วนเป็นการทำข้อสอบคนเดียวไม่มีแรงกดดัน — ไม่มีโหมดไหนเลยที่ให้
"ความรู้สึกสอบจริง" (มีเวลาจำกัด ต้องตัดสินใจเร็ว) และไม่มีโหมดเรียนไหนเทียบกับเพื่อนทั้งรุ่นได้
สนามประลอง/หอคอยมีกระดานให้แข่ง แต่ฝั่งเรียนไม่มีเลย

## หลักการ

**เวลาคือทรัพยากร** — ทุกวินาทีที่ใช้อ่านอะไรก็ตามคือคะแนนที่หายไป
⇒ ระหว่างเล่นไม่มีอะไรให้อ่านนอกจากโจทย์ · คำอธิบายทั้งหมดยกไปไว้ที่จอผล

## ขอบเขต

หน้าแยก `/study/time-attack` → `views/TimeAttackView.vue` (แพทเทิร์นเดียวกับ `/study/crcl`)
**ไม่ยัดเข้า `QuizView.vue`** — 677 บรรทัดแล้ว และจังหวะเล่น/จอผล/กระดานคนละเรื่องกับโหมดอื่นทั้งหมด
(ที่ใช้ร่วมกันจริงมีอย่างเดียวคือการสุ่มดึงโจทย์ → แยกเป็น composable ให้ทั้งสองหน้าใช้)

## การเล่น

1. **หน้าเลือก** — 2 ปุ่ม: ⚡ 4 นาที · 🔥 15 นาที · ใต้ปุ่มโชว์สถิติดีสุดของตัวเอง + กระดานอันดับในรุ่น
   **ไม่ให้เลือกหมวด/ชุดย้อนหลัง** — ทั้งรุ่นต้องเจอกติกาเดียวกันถึงจะเทียบคะแนนกันได้
2. **ระหว่างเล่น** — นาฬิกานับถอยหลังบนหัวจอ + `ถูก x / ตอบไป y` สดๆ
   - แตะตัวเลือก → ไฟเขียว (ถูก) / แดง+เน้นข้อที่ถูก (ผิด) **0.4 วิ** → ขึ้นข้อถัดไปเอง ไม่มีปุ่มกด
   - ไม่มีคำอธิบาย ไม่มีปุ่มแจ้งข้อผิด ไม่มีแถบ progress (ไม่รู้ว่าจะได้กี่ข้อ)
   - 10 วินาทีสุดท้าย นาฬิกาเปลี่ยนเป็นสีแดง + เต้น
   - หมดเวลา = จบทันที แม้กำลังค้างอยู่ที่ข้อไหน (ข้อที่ยังไม่ตอบไม่นับทั้งถูกและผิด)
   - ปุ่ม ✕ ออกกลางคัน = จบรอบและบันทึกผลเท่าที่ทำได้ (เหมือน `quit()` ของ QuizView)
3. **จอผล** — คะแนน (จำนวนข้อถูก) · ความแม่น % · เหรียญที่ได้ · เทียบสถิติเดิม (ทำลายสถิติ = ป้าย 🎉)
   + **รายการข้อที่ตอบผิด พร้อมเฉลยและคำอธิบาย** ไล่ดูได้ทั้งหมด (นี่คือของที่แลกมาจากการไม่โชว์ระหว่างเล่น)
   + กระดานอันดับในรุ่นของเวลานั้น

## นาฬิกา

`endAt = Date.now() + durationMs` ตอนเริ่ม · ทุก tick คำนวณ `endAt - Date.now()` ใหม่
**ห้ามสะสมเวลาจาก tick** — สลับแอปแล้ว `setInterval` ถูก throttle บนมือถือ เวลาจะเดินช้ากว่าจริง
⇒ สลับแอปกลับมาแล้วนาฬิกาเดินไปตามเวลาจริง (ไม่มีการหยุดพักให้ ตั้งใจ)

tick ที่ 200ms (ไม่ใช่ 1000ms) — เลขวินาทีจะได้ไม่กระตุกเวลาเปลี่ยน และการจบรอบไม่คลาดเกิน 0.2 วิ

## คลังข้อ (จุดที่ต้องออกแบบจริง)

15 นาทีตอบได้ ~150 ข้อ = **150 reads ต่อรอบ** ถ้าดึงทีเดียวก่อนเริ่มจะรอนานและจ่ายค่าอ่านของข้อที่ไม่ได้ทำ

⇒ **ล็อตละ `TA_BATCH = 25` ข้อ · ยิงล็อตถัดไปเมื่อเหลือ ≤ 8 ข้อในคิว**
ยิงแบบ fire-and-forget (ไม่ `await` ในเส้นทางที่ผู้เล่นรออยู่) — นาฬิกาไม่มีวันหยุดรอเน็ต
ถ้าเน็ตช้าจนคิวหมดจริง โชว์ "กำลังโหลดข้อถัดไป…" แล้วเล่นต่อเมื่อมาถึง (เวลายังเดิน — ตั้งใจ ไม่ให้ปั่นเน็ตช้าเป็นการหยุดเวลา)

คลังหมดจริง (ดึงมาแล้วไม่มีข้อใหม่) = จบรอบก่อนเวลาพร้อมข้อความ "ทำครบทุกข้อในคลังแล้ว!"

**กันข้อซ้ำในรอบเดียว** — เก็บ `Set` ของ id ที่เคยเสิร์ฟ กรองล็อตใหม่ก่อนต่อคิว
(`orderBy('rand')` + `startAt(random)` สุ่มซ้ำได้ตามธรรมชาติ ยิ่งคลังเล็กยิ่งซ้ำบ่อย)

## คะแนน / เหรียญ / SRS

- คะแนน = จำนวนข้อที่ **ตอบถูก** (ตอบผิดไม่หักคะแนน แต่กินเวลา = โทษในตัวมันเอง)
- เหรียญ = `ถูก × QUIZ_COIN_PER_CORRECT (100)` เท่าโหมดปกติ — สอดคล้องกับหลัก "ทำมากได้มาก" (11 ก.ค.)
  ตอบเร็วได้เยอะเพราะแม่นจริง ไม่ใช่ช่องโหว่ · ไม่มี combo/streak multiplier (จะทำให้ตอบมั่วรัวคุ้มกว่าคิด)
- ข้อที่ผิด → เข้ากอง `study.qcards` ผ่าน `applyQuizResults(variant:'normal')` เหมือนโหมดทั่วไป
- `quizDoneTotal` + `bumpDailyQuest('quiz', ...)` เหมือนโหมดอื่น
- บันทึก `examSessions` 1 doc ต่อรอบ พร้อมฟิลด์ `mode: 'ta4' | 'ta15'` (เดิม doc ไม่มีฟิลด์นี้ = โหมดปกติ)
  ⇒ ประวัติ/กราฟพัฒนาการใน QuizView นับรวมให้เอง ไม่ต้องแก้ `aggregateExamStats`
- สถิติรายข้อ `questionStats` — เขียนเหมือน QuizView (batch increment)

## อันดับในรุ่น

สถิติดีสุดเก็บใน user doc: `timeAttack: { best4, best15 }` (ผ่าน `USER_DEFAULTS`)
แถว roster เพิ่ม 2 คีย์ **ใส่ต่อเมื่อ > 0** (แบบเดียวกับ `m` — กันแถวบวมด้วยศูนย์):
```js
ta4: 23, ta15: 61
```
กระดานอ่านจาก `members.rosterRows` ที่โหลดอยู่แล้ว ⇒ **0 read เพิ่ม**

⚠️ ใช้ `rosterRows` **ไม่ใช่ `rosterUsers`** — `rosterUsers` คีย์ด้วย studentId จึงตก guest ทั้งหมด
(บทเรียนจากหอคอย 23 ส.ค.) นักศึกษา guest ก็ทำข้อสอบและควรอยู่บนกระดาน

overlay "ฉัน" ด้วยค่าสดจาก user doc เหมือน `useMinigameBoard` — roster อาจยังไม่ทัน sync

โชว์ 10 อันดับ · ถ้าเราไม่ติด 10 ต่อท้ายแถวของเราพร้อมอันดับจริง (ไม่งั้นคนที่อันดับ 30 ไม่เห็นตัวเองเลย)

## สิ่งที่จะไม่ทำ

- ไม่ผูกกับ registry มินิเกม (`data/minigames.js`) — `arcadeOpen` ปิดอยู่ แต่ Time Attack เป็นของฝั่งเรียน ต้องเปิดตลอด
- ไม่มีโหมดแข่งสด/ห้องแข่ง (ต้องมี backend)
- ไม่มี combo multiplier / คะแนนโบนัสตามความเร็ว
- ไม่ให้เลือกหมวด (จะเทียบคะแนนกันไม่ได้)
- ไม่มีปุ่มแจ้งข้อผิดระหว่างเล่น (มีในจอผล? — ไม่ทำเช่นกัน รอบนี้เอาให้จบง่ายก่อน)

## ข้อจำกัดที่ต้องรู้

- **นาฬิกาอยู่ฝั่ง client ⇒ แก้ได้ถ้าตั้งใจ** — trust-based เหมือนทั้งแอป · ผลเสียจำกัดที่ "ชื่อบนกระดาน"
  และเหรียญ ซึ่งได้จากโหมดปกติไม่จำกัดอยู่แล้ว ⇒ ไม่คุ้มจะกัน
- แอดมินกด "สร้าง roster ใหม่" แล้ว `ta4/ta15` ยังอยู่ (มาจาก user doc) — ต่างจาก `h` ของประวัติ PvP
- คลังข้อปัจจุบันอาจไม่ถึง 150 ข้อในบางช่วง ⇒ โหมด 15 นาทีจะจบก่อนเวลา เป็นพฤติกรรมที่ตั้งใจ ไม่ใช่บั๊ก
