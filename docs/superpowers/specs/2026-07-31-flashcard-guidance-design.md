# แฟลชการ์ดอธิบายตัวเองได้ — Design (31 ก.ค. 2026)

## เป้าหมาย

คนเปิดแฟลชการ์ดต้องรู้ว่า **ต้องนึกอะไรออกบ้าง** และ **กลไกนี้ใช้ยังไง** โดยไม่ต้องมีใครสอน

ที่มา: user บอก 31 ก.ค. ว่า "ระบบแฟลชการ์ดยังไม่ค่อยดี" แล้วระบุเองว่าปัญหาคือ
**"ผู้เล่นไม่ทราบว่าต้องบอกข้อมูลอะไรบ้าง ไม่รู้วิธีใช้แฟลชการ์ด"**
⇒ ไม่ใช่ปัญหาอัลกอริทึม เด็ค จังหวะ หรือเศรษฐกิจ · user เลือกขอบเขต **"บอกให้รู้ — ไม่แตะกลไก"**

งานคู่กัน (ทำไปแล้ว commit `7e5e6d1`): ถอดแฟลชการ์ดออกจากการ์ด "ทำอะไรต่อ" หน้า Home ตามที่ user สั่ง

## สภาพปัจจุบัน (อ่านโค้ดแล้ว 31 ก.ค.)

`src/views/StudyView.vue` (424 บรรทัด) · เด็ค = `DRUGS` 78 ตัวยา ฟิลด์ `{ n, a, ind, dose }`

- **หน้าการ์ดก่อนพลิก** มีแค่ป้าย `ตัวยา` + ชื่อยา + `แตะเพื่อดูเฉลย` — **ไม่มีอะไรบอกว่าต้องนึกอะไร**
  ⇒ คนแตะดูเฉลยทันที ซึ่งทำลายคุณค่าทั้งหมดของแฟลชการ์ด (คุณค่าอยู่ที่ *พยายามนึกก่อน*)
- **ป้ายหลังพลิกเขียนว่า `กลุ่ม / กลไก`** แต่ของจริงมี 3 ก้อน: กลุ่มยา (`a`) · ข้อบ่งใช้ (`ind`) · ขนาด (`dose`) — ป้ายไม่ตรง
- **ปุ่มให้คะแนน** `ลืม / ยาก / จำได้ / ง่าย` มีแต่ตัวเลขวันกำกับ ไม่มีคำอธิบายว่าแต่ละปุ่มแปลว่าอะไร
  และไม่บอกว่าปุ่มพวกนี้เป็นตัวกำหนดว่าการ์ดจะกลับมาเมื่อไหร่ · คนไม่เคยใช้ SRS แยก "ยาก" กับ "จำได้" ไม่ออก
- **ไม่มีคำสอนตอนเริ่มใช้** — มีหัวข้อ ℹ️ `study` อยู่ แต่เป็น pull ต้องกดเอง และเนื้อหาไม่ได้สอนวิธีใช้การ์ด

## 🐞 บั๊กที่เจอระหว่างเตรียมแผน (ไม่ได้อยู่ในคำสั่งเดิม แต่เกี่ยวตรง)

**บั๊ก A (severity สูง — ทำให้ SRS ไม่ทำงานเลย):** `StudyView.vue:39`
```html
<button class="sv-start" :disabled="!queueSize" @click="startSession">
```
Vue ส่ง native event เป็นอาร์กิวเมนต์แรกเมื่อผูก method โดยไม่ใส่วงเล็บ ⇒ `startSession(free = false)` ได้
`free = PointerEvent` ซึ่ง **truthy** ⇒ ปุ่มหลัก "เริ่มทบทวน N ใบ" เข้าสาขา `if (free)` **สุ่ม 20 ใบจากทั้งเด็ค**
ไม่สนคิวครบกำหนดเลย · ปุ่มบอกจำนวนหนึ่งแต่ให้อีกอย่าง และตาราง SM-2 ทั้งระบบถูกข้าม
**แก้:** `@click="startSession()"` (ใส่วงเล็บ) — บรรทัดเดียว
**นี่คือบั๊ก ไม่ใช่การเปลี่ยนกลไก** — เป็นการทำให้กลไกที่ออกแบบไว้แล้วทำงานจริง จึงอยู่ในขอบเขต "ไม่แตะกลไก"

**บั๊ก B (severity กลาง — ข้อความไม่ตรงพฤติกรรม):** ปุ่มฝึกอิสระเขียนว่า `(ไม่บันทึกความคืบหน้า)` แต่
`grade()` ไม่เคยเช็ก `free` ⇒ ฝึกอิสระ **บันทึก SRS + เลื่อนตาราง + ให้เหรียญ** ตามปกติ
**ตัดสินใจ:** รอบนี้ **แก้แค่ข้อความให้ตรงความจริง** ไม่แตะพฤติกรรม เพราะการทำให้ "ไม่บันทึกจริง" =
เปลี่ยนกลไก + ตัดทางได้เหรียญ ซึ่ง user ไม่ได้สั่งและไม่อยู่ตอนนี้ · **บันทึกไว้ให้ user ตัดสินรอบหน้า**

## การตัดสินใจของ controller (user ออกไปข้างนอก สั่งให้ทำต่อจนจบ)

1. **บรรทัด "ลองนึกให้ได้" โชว์ทุกใบเสมอ** — ไม่ทำระบบจาง/ซ่อนเมื่อชิน เพราะต้องเพิ่ม state + กฎที่ไม่มีใครขอ (YAGNI)
2. **คงปุ่ม 4 ระดับ** — user สั่งชัดว่าไม่แตะกลไก การลดเหลือ 2–3 ปุ่มคือเปลี่ยน SM-2 mapping
3. **เพิ่มลิงก์ "ดูวิธีใช้อีกครั้ง" บนหน้า Study** — ไม่งั้นจอสอนดูซ้ำไม่ได้เลยหลังกดผ่านครั้งแรก
4. **คำที่ใช้ยึดของเดิมในจอ** — `ขนาด (ผู้ใหญ่)` มีอยู่แล้วในแผงเฉลย จึงใช้ "ขนาดผู้ใหญ่" ให้ตรงกัน

## 1. หน้าการ์ดก่อนพลิก

เพิ่มบล็อกเหนือ `แตะเพื่อดูเฉลย` (เห็นเฉพาะตอนยังไม่พลิก):

```
ลองนึกให้ได้ก่อนเปิด
กลุ่มยา · ข้อบ่งใช้ · ขนาดผู้ใหญ่
```

รายการ 3 อย่างนี้ **คงที่** เพราะทุกการ์ดในเด็คมีสามฟิลด์นี้เท่ากันหมด (ไม่ต้อง derive)

ป้ายหลังพลิก `กลุ่ม / กลไก` → **`เฉลย`** (ตรงกับของจริงที่มี 3 ก้อน)

## 2. ปุ่มให้คะแนน

เหนือแถวปุ่ม เพิ่มโน้ต 1 บรรทัด:
> ตอบตามจริง — ปุ่มที่เลือกกำหนดว่าการ์ดนี้จะกลับมาเมื่อไหร่

แต่ละปุ่มเพิ่มบรรทัดกลางเป็นความหมายภาษาคน (บนสุด = ป้ายเดิม, ล่างสุด = ช่วงเวลาเดิมที่คำนวณสด):

| ปุ่ม | ความหมายที่เพิ่ม |
|---|---|
| ลืม | นึกไม่ออก |
| ยาก | ต้องคิดนาน |
| จำได้ | นึกออกปกติ |
| ง่าย | ตอบได้ทันที |

⚠️ 4 ปุ่มเรียงแนวนอนบนมือถือ — บรรทัดที่สามต้องเล็ก (~.58rem) และข้อความสั้นตามตารางนี้เป๊ะ
ห้ามยาวกว่านี้ ไม่งั้นตัดคำเสียรูปบนจอ 360px · `grade(q)` ที่ปุ่มเรียกและค่า q เดิม (1/3/4/5) **ห้ามเปลี่ยน**

## 3. จอสอนครั้งแรก — เป็นโหมดในหน้า ไม่ใช่ overlay

เพิ่มค่า `coach` เข้าไปในสเตตเดิม `mode` (`home | review | done` → `+ coach`)

**เหตุผลที่ไม่ทำเป็น overlay:** `StudyView` render อยู่ใต้ `<RouterView>` ⇒ overlay `position:fixed` ต้องห่อ
`<Teleport to="body">` (กับดักข้อ 6 ใน CLAUDE.md ที่วนกลับมา ≥5 รอบ) · ทำเป็นโหมดในหน้าแล้วไม่ต้องเสี่ยงเลย

**เมื่อไหร่:** กด "เริ่มทบทวน" แล้ว ถ้า `!seenStudyCoach` → `mode = 'coach'` · จบขั้น 3 → ประทับ flag แล้วเข้าเซสชันต่อทันที
· มีปุ่ม "ข้าม" ทุกขั้น (ข้าม = ประทับ flag + เข้าเซสชันเหมือนกัน ไม่ใช่กลับหน้าหลัก)

**เนื้อหา 3 ขั้น:**
1. **พยายามนึกก่อน** — เห็นชื่อยาแล้วอย่าเพิ่งเปิดเฉลย · การพยายามนึกคือสิ่งที่ทำให้จำได้จริง ไม่ใช่การอ่านซ้ำ
2. **เปิดแล้วเทียบ** — ดูว่านึกได้ครบ 3 อย่างไหม (กลุ่มยา · ข้อบ่งใช้ · ขนาดผู้ใหญ่)
3. **ตอบตามจริง** — ปุ่มที่กดกำหนดว่าการ์ดจะกลับมาเมื่อไหร่ · ตอบเกินจริงจะไปลืมเอาตอนสอบ

**ดูซ้ำได้:** หน้า Study (`mode === 'home'`) เพิ่มลิงก์เล็ก "ดูวิธีใช้แฟลชการ์ดอีกครั้ง" → `mode = 'coach'`
โดย**ไม่**เข้าเซสชันต่อเมื่อจบ (กลับ `home`) — แยกจากเส้นทางครั้งแรกด้วย ref ในหน้า ไม่ต้องเพิ่มฟิลด์ใน Firestore

**flag:** `seenStudyCoach: false` ประกาศใน `src/data/userSchema.js` (`USER_DEFAULTS`) · เขียนผ่าน
`auth.patchUser({ seenStudyCoach: true }, { seenStudyCoach: true })` · `firestore.rules` ฝั่ง `users/{userId}`
ไม่มี `hasOnly` ⇒ **ไม่ต้องแก้ rules**

## 4. หัวข้อ ℹ️ `study`

เขียนใหม่ให้สอนวิธีใช้จริง ≤4 บรรทัด: นึกก่อน → เปิดเทียบ → ตอบตามจริง + ความหมายของ 4 ปุ่มโดยย่อ
คงข้อมูลเดิมที่ยังจริงไว้ (ทบทวนได้เหรียญ · ระบบนัดวันให้เอง)

## การทดสอบ

งานนี้เป็น UI/copy ล้วน **ไม่มี pure util ใหม่** ⇒ ไม่มีอะไรให้ `node --test`
ตรวจด้วย `npm run build` + เทสจอจริง (user) · เทสเดิม 123 ตัวต้องยังผ่าน (ไม่ควรถูกแตะ)

**สิ่งที่ user ต้องเทสบนมือถือ:**
1. บัญชีที่ยังไม่เคยเห็น coach → กด "เริ่มทบทวน" → เจอจอสอน 3 ขั้น → จบแล้วเข้าเซสชันทันที · กด "ข้าม" ก็เข้าเซสชันเหมือนกัน
2. กดเริ่มทบทวนรอบสอง → **ไม่เจอจอสอนอีก** (flag ติด)
3. ลิงก์ "ดูวิธีใช้แฟลชการ์ดอีกครั้ง" → เห็นจอสอน → จบแล้ว**กลับหน้าหลัก** ไม่ใช่เข้าเซสชัน
4. หน้าการ์ดก่อนพลิกเห็นบรรทัด "ลองนึกให้ได้ก่อนเปิด กลุ่มยา · ข้อบ่งใช้ · ขนาดผู้ใหญ่"
5. พลิกแล้วป้ายเขียนว่า "เฉลย" · ปุ่ม 4 ปุ่มมี 3 บรรทัด อ่านออกครบ ไม่ตัดคำบนจอแคบ
6. กดปุ่มแล้วช่วงเวลาทบทวนยังทำงานเหมือนเดิมทุกประการ (ไม่ได้แตะ SM-2)
7. **สำคัญ (บั๊ก A):** ปุ่ม "เริ่มทบทวน N ใบ" ต้องให้การ์ด **N ใบตามที่เขียนบนปุ่ม** และต้องเป็นการ์ดที่
   ครบกำหนด/ยังไม่เคยเรียนจริง — ไม่ใช่สุ่ม 20 ใบจากทั้งเด็ค (ตัวเลขบนแถบ `x/y` ตอนทบทวนต้องตรงกับปุ่ม)

## ข้อจำกัดที่ยอมรับ

- บรรทัด "ลองนึกให้ได้" กินพื้นที่การ์ดถาวร แม้คนที่ชินแล้ว — แลกกับการไม่เพิ่ม state/กฎซ่อน
- จอสอนโผล่ครั้งเดียวต่อบัญชี · คนที่กดข้ามเร็วเกินต้องไปหาลิงก์ดูซ้ำเอง (จึงต้องมีลิงก์นั้น)
- ไม่มีเทสอัตโนมัติคุมงานนี้เลย — พึ่ง `npm run build` กับตาคนล้วน
