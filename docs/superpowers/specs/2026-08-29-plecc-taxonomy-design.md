## วิธีเก็บบนข้อ — additive ไม่รื้อของเดิม

```
pleGroup : 'endo'                 ← แหล่งความจริงใหม่ (key จาก plecc.js)
pleSub   : 'Diabetes mellitus'    ← โรคย่อย (null ได้)
categories: ['Endocrine (ต่อมไร้ท่อ)', 'Diabetes mellitus']   ← ระบบเขียนให้เอง
```

**`categories` กลายเป็นค่าที่ derive ได้เสมอจาก `pleGroup`/`pleSub`** (`categoriesFor()`)
⇒ quiz filter · `questionsMeta` · หน้าคลัง · exam stats · SRS **ไม่ต้องแก้สักบรรทัด**
⇒ และ **re-derive ได้ตลอด** — นี่คือกลไกกันพังจาก client เก่า (ดูหัวข้อถัดไป)

`config/topics.list` เลิกโตเอง (ตัดปุ่ม "➕ เพิ่มหัวข้อใหม่" ทิ้ง — นี่คือต้นเหตุที่งอก 82 หมวด)
ทะเบียนยังอยู่เฉยๆ ไม่ลบในรอบนี้ (กล่อง "จัดการหมวด" ยังใช้ล้างซากได้)

## 🔴 ข้อจำกัดสำคัญ: เพื่อนอาจกำลังตรวจอยู่ตอนนี้

client เก่าที่เปิดหน้า `/review` ค้างไว้จะยัง submit ด้วยโค้ดเดิม ซึ่งเขียน `categories`
เป็น free text ชุดเก่า → **ทับผลการ migrate ของข้อนั้น**

**กันด้วยหลักการ "categories เป็นค่า derive ได้":**
1. client เก่าเขียนทับได้แค่ `categories` — **`pleGroup`/`pleSub` ไม่อยู่ใน `reviewSubmitKeys` เดิม
   ของ client เก่า มันจึงแตะไม่ได้เลย** ⇒ แหล่งความจริงรอดเสมอ
2. ปุ่มซิงก์ของแอดมิน re-derive `categories` จาก `pleGroup` ให้ใหม่ ⇒ **หายเองรอบถัดไป**
3. worst case = ข้อนั้นป้ายหมวดเพี้ยนชั่วคราว ไม่ใช่ data loss

**ลำดับ deploy (ห้ามสลับ):**
1. `firebase deploy --only firestore:rules` — เพิ่ม `pleGroup`/`pleSub` เข้า `reviewSubmitKeys`
   (additive: client เก่าไม่กระทบ · ถ้าไม่ทำก่อน client ใหม่จะ submit ไม่ผ่าน permission)
2. `git push` — ขึ้นโค้ดใหม่
3. แอดมินกด **"🔄 แมพหมวดเข้าเกณฑ์สภาฯ"** ตอนที่ไม่มีคนตรวจค้าง (ดึกๆ / ประกาศก่อน)

**ไม่แตะ `qhash`** ⇒ `reviewContentChanged` ไม่นับการเปลี่ยนหมวด ⇒
การ migrate **ไม่ทำให้รีวิวที่ค้างอยู่กลายเป็น `__stale`** และไม่ล้างผลตรวจของใคร
