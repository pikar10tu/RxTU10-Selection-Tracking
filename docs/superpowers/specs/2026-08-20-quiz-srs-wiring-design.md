# ต่อสาย Quiz → SRS (ข้อที่เคยผิด) — Design

วันที่ 20 ส.ค. 2026 · สถานะ: อนุมัติแล้ว (user 20 ส.ค.) · HEAD ตอนออกแบบ `0d7da86`

## ปัญหา

ทำข้อสอบผิดแล้ว**ไม่มีอะไรเกิดขึ้น** — `QuizView.vue` ไม่เคยเขียน `study.*` เลย
ทั้งที่ `utils/sm2.js` (`sm2Update`/`newSrsCard`) พร้อมใช้ตั้งแต่แรก และ `finish()` ถือ
`answers = [{ id, domain, correct }]` อยู่ในมือแล้ว

ผลคือแฟลชการ์ด SRS ผูกกับ deck ตายตัว (ยา 78 ตัวใน `DRUGS`) เท่านั้น
คลังข้อสอบไม่เคยไหลเข้าระบบทบทวนเลย — ค้างมาตั้งแต่ มิ.ย. (ROADMAP Phase 2 ข้อ 1)

เหลือ ~113 วันถึง PLE CC (11 ธ.ค. 2026) — นี่คือช่องว่างที่เจ็บที่สุดของฝั่งการเรียน

## ขอบเขต

**ทำ:** ข้อที่ตอบผิดกลายเป็นการ์ด SRS → กลับมาทบทวนด้วยการ**ตอบข้อนั้นใหม่** → ตอบถูกติดกัน 3 ครั้งแล้วหลุดกอง

**ไม่ทำ (YAGNI ตัดออกโดยตั้งใจ):** badge บน Home · เลือกหมวดในโหมด redo ·
สถิติรายข้อเพิ่มเติม · ยุ่งกับ `study.cards` (แฟลชการ์ดตัวยา) เดิม

## 1. Data model

map ใหม่บน user doc **แยกกองจาก `study.cards`** (ที่ key ด้วยชื่อยา):

```js
study.qcards = {
  "<questionId>": { e: 2.5, i: 1, r: 0, l: 1, t: 1, d: 1755648000000 }
}
```

| คีย์ | ความหมาย | มาจาก |
|---|---|---|
| `e` | easeFactor | `sm2Update` |
| `i` | interval (วัน) | `sm2Update` |
| `r` | repetitions (ถูกติดกันกี่ครั้ง) | `sm2Update` |
| `l` | lapses (ผิดสะสม) | นับเอง |
| `t` | totalReviews | นับเอง |
| `d` | dueAt (epoch ms) | `nextReviewDate.getTime()` |

**ทำไมคีย์สั้น:** ออดิต 13 ส.ค. เตือน user doc บวม — `study.cards` 78 ตัวยาที่ใช้ชื่อฟิลด์เต็ม
(`easeFactor`/`nextReviewDate`/…) กินแล้ว ~16KB · คลังข้อสอบไม่มีเพดานจำนวน
ชื่อเต็ม 200 ข้อ ≈ 40KB vs ชื่อสั้น ≈ 12KB · user doc อ่านใหม่ทุก `onSnapshot`

**ไม่แตะ `sm2.js`** — โมดูลใหม่ `utils/srsQuestions.js` มี `unpackCard()`/`packCard()`
แปลงคีย์สั้น ↔ รูปแบบที่ `sm2Update()` รับ

**ไม่เก็บเนื้อโจทย์ในกอง** — เก็บแค่ id ตัวโจทย์ดึงสดจาก `questions/{id}` ตอนเริ่มรอบ
(กัน user doc บวมและกันโจทย์ค้างเวอร์ชันเก่าหลังทีมวิชาการแก้)

### กฎจบการ์ด (สำคัญ)

ตอบถูกติดกันครบ **3 ครั้ง** (`r >= 3`) → **ลบ key ทิ้งด้วย `deleteField()`**

เหตุผลสองชั้น: (1) map ไม่โตไม่จำกัด — bound ตัวเองตามธรรมชาติ
(2) โหมดนี้คือ "กองข้อที่เคยผิด" ไม่ใช่คลังถาวร — เคลียร์จนหมดกองคือ loop ที่อยากได้

## 2. Flow

| เหตุการณ์ | ผลต่อ `qcards` |
|---|---|
| ควิซปกติ/Zen **ตอบผิด** — ยังไม่มีการ์ด | สร้างการ์ดใหม่ `d = now` (**due ทันที**) `l=1 t=1 r=0` |
| ควิซปกติ/Zen **ตอบผิด** — มีการ์ดแล้ว | `sm2Update(card, 1)` · `l++` `t++` · `d = now` (**due ทันที**) |
| ควิซปกติ/Zen **ตอบถูก** | ไม่แตะเลย (แม้ข้อนั้นมีการ์ดค้างอยู่) |
| โหมด redo **ตอบถูก** | `sm2Update(card, 4)` · `t++` → ถ้า `r >= 3` ลบ key ทิ้ง |
| โหมด redo **ตอบผิด** | `sm2Update(card, 1)` · `l++` `t++` · `d = now + 1 วัน` |

### กฎวันครบกำหนด (`d`)

- **ตอบผิดในควิซปกติ/Zen → `d = now` (โผล่ในกองทันที)** — เพิ่งพลาดไปเมื่อกี้ ควรได้แก้วันนี้เลย
  (ตรงกับคอมเมนต์ของ `newSrsCard` เอง: *due immediately on first encounter*)
  และกัน UX ประหลาดที่ทำข้อสอบพังทั้งชุดแล้วการ์ดยังขึ้น "ยังไม่มีข้อค้าง"
- **ตอบผิดในโหมด redo → `d = now + 1 วัน`** — ฝึกไปแล้ววันนี้ ไม่ต้องวนซ้ำในวันเดียว
- **ตอบถูกในโหมด redo → `d = now + interval × 1 วัน`** ตาม `sm2Update`

⚠️ คำนวณ `d` จาก `now` ที่ inject เข้ามา **ไม่ใช่** `u.nextReviewDate` (ซึ่ง `sm2.js` อิง `Date.now()`
ภายในตัวเอง) — เพื่อให้ฟังก์ชันเป็น pure และเทสได้แบบ deterministic

"ตอบถูกในควิซปกติไม่แตะกอง" เป็นความตั้งใจ — กฎอธิบายง่าย ("ผิดเข้ากอง แก้ได้ในโหมด redo")
และเลี่ยงการเกรดซ้อนจากข้อที่ sampler บังเอิญสุ่มมาเจอ

### การเขียน

`finish()` ใน `QuizView.vue` เรียก `patchUser()` อยู่แล้ว 1 ครั้ง → **เติมฟิลด์ลง patch ก้อนเดิม
= เขียน Firestore เพิ่ม 0 ครั้ง**

ตามแพทเทิร์นบ้าน (CLAUDE.md + minigames): `server` ใช้ **dot-notation**
`'study.qcards.<qid>'` / `deleteField()` · `optimistic` deep-merge เอง
(`setUserDataOptimistic` เป็น shallow spread — ส่ง dot key เข้าไปจะได้คีย์ literal)

⚠️ **ห้ามเขียน `study: {...}` ทั้งก้อนจาก QuizView** — จะทับ `study.cards` ของแฟลชการ์ด
(กับดักเดิม: `progress: {}` ใน set(merge) ล้าง map ทั้งก้อน)

`data/userSchema.js` เพิ่ม default `study: { cards: {}, qcards: {} }` + normalize ให้ user เก่า

## 3. UI — ไม่มีหน้าจอใหม่

### StudyView
เพิ่ม `QuizModeCard` ใบที่ 6 ในหมวด "📝 ทำข้อสอบ":

```
🔁 ข้อที่เคยผิด — "ครบกำหนดทบทวน N ข้อ"  → /quiz?mode=redo
```

- `N` = จำนวน entry ใน `qcards` ที่ `d <= now` — นับจาก user doc ที่โหลดอยู่แล้ว = **0 reads**
- `N = 0` → การ์ดยัง**กดได้** แต่ subtitle เปลี่ยนเป็น "ยังไม่มีข้อค้าง — ตอบผิดเมื่อไหร่จะเก็บมาที่นี่"
  และเข้าไปเจอหน้าจบแบบนุ่มนวล (ไม่ทำให้กดแล้วเงียบ)

### QuizView
เพิ่ม `variant = 'redo'` ตัวที่สาม (มี `normal` / `zen` อยู่แล้ว) — โจทย์ ตัวเลือก เฉลย
💡คำอธิบาย 📝หมายเหตุผู้ตรวจ 🚩แจ้งข้อผิด หน้าสรุปผล **ใช้ของเดิมทั้งหมด ไม่แตะ**

`startRedo()`:
1. อ่าน `qcards` → กรอง `d <= now` → เรียง `d` เก่าสุดก่อน → ตัดที่ **20 ข้อ**
2. ดึงโจทย์: `query(collection(db,'questions'), where(documentId(), 'in', chunk))` ทีละ 30
   (20 ข้อ = 1 query, ~20 reads ต่อรอบ) · `usage.track(n, 0)`
3. กรองข้อที่หายไป/ถูกถอนเผยแพร่ (`!isPublished` หรือไม่มี doc) ออก **และเก็บ id ไว้ลบจาก
   `qcards` ตอน `finish()`** — กันกองค้างข้อผี
4. `shuffleChoices()` ตามปกติ · ป้ายหัวรอบเป็น `🔁 ข้อที่เคยผิด`

`pick()` ไม่ต้องแก้ — บันทึก `{id, domain, correct}` ครบอยู่แล้ว

## 4. เหรียญ

**เหมือนควิซปกติเป๊ะ** — `QUIZ_COIN_PER_CORRECT` ต่อข้อที่ถูก **ไม่มีเพดานรายวัน**

⚠️ ห้ามใส่ cap กลับเข้าควิซโดยคิดว่าเป็นบั๊ก — user สั่งปลดเพดานไว้ตั้งใจ 11 ก.ค.
(commit `486a8a8`, "ทำมากได้มาก") · เพดานที่ยังเหลืออยู่คือฝั่งแฟลชการ์ด StudyView เท่านั้น

รับทราบช่องโหว่: ตั้งใจตอบผิดแล้วมา redo เก็บซ้ำได้ — แต่ต้องขยันอ่านโจทย์จริงทุกครั้ง
และ `r >= 3` ดันข้อออกจากกอง user ยอมรับ trade-off นี้แล้ว

## 6. เทส (`node --test`)

1. ตอบผิดข้อใหม่ → มีการ์ด `d === now` (due ทันที) `l=1 t=1 r=0`
2. ตอบผิดข้อที่มีการ์ดแล้ว (ควิซปกติ) → `l` เพิ่ม `r=0` `d === now`
3. ตอบถูกในควิซปกติ → กองไม่เปลี่ยนเลย (แม้มีการ์ดค้าง)
4. redo ตอบถูก 1–2 ครั้ง → การ์ดยังอยู่ `i` ยืดออก
5. redo ตอบถูกครบ 3 ครั้งติด → key หายจากกอง (คืนสัญญาณให้ผู้เรียกใช้ `deleteField()`)
6. redo ตอบถูก 2 ครั้งแล้วผิด → `r` รีเซ็ต ไม่หลุดกอง `d === now + 1 วัน`
7. `packCard`/`unpackCard` ครบรอบค่าเท่าเดิม
8. `dueQuestionIds` เรียง due เก่าสุดก่อน + ตัดที่ limit + ข้ามข้อที่ยังไม่ครบกำหนด
9. ข้อที่หายจากคลัง → อยู่ในรายการที่ต้องลบทิ้ง

## 7. ความเสี่ยง

| ความเสี่ยง | กัน |
|---|---|
| เขียนทับ `study.cards` | dot-notation เท่านั้น + เทส + ระบุใน plan ชัด |
| user doc บวม | คีย์สั้น + กฎจบการ์ด `r>=3` + ไม่เก็บเนื้อโจทย์ |
| `in` query เกิน 30 | chunk + รอบละ 20 อยู่แล้ว |
| ข้อถูกลบ/ถอนเผยแพร่ | กรองออก + ลบ key ทิ้งอัตโนมัติ |
| `patchUser` คืน false | toast แจ้ง + กองไม่เปลี่ยน (rollback ให้แล้วใน store) |
